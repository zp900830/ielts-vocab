## W1 · 任务模式顶栏补齐（PRD §4.3 / §8.1）—— 最大的一条

**症状**：`/app/` fork 自影子跟读后，旧 `header.topbar` 被 `body > .topbar{display:none}` 隐藏，于是那一排开关**全部不可达**：
`#btnZh`（译文开关）、`#btnGloss`（行内词义）、`#btnAccent`（英/美口音）、音色选择、`#btnDark`（夜间模式）。
PRD §4.3 明确写「译文开关 / 行内词义开关 / 口音+音色切换 → 顶栏（沿用 `header.topbar` 的控件，但收窄为一条）」；
§8.1 写「深色切换放顶栏」。

**要求**：让这些开关在 `/app/` 里真的能用。做法自选（推荐：把需要的节点搬进 T5 建的那条任务模式顶栏 `.task-top`，或另建一条常驻外壳顶栏 —— 关键是**不是靠 CSS 藏起来**）。
至少覆盖：译文开关、行内词义开关、英/美口音、夜间模式。音色选择若搬过来代价大，可在报告里说明并留到 M4（随身听那期本来就要碰音色）。

**锁**：E2E 断言这些控件可见且点得动 —— 点译文 → 译文真的显示/隐藏；点夜间 → `body.dark` 真的切换且**新外壳的观感跟着变**。

## W2 · 深色全覆盖（PRD §10.1 的 token 要求）

新外壳与 M1 新页面**没有任何 `body.dark` 覆盖**：`.sidenav` / `.nav-item` / `.art-card`（含四档状态）/ `#appView` / `.task-top` / `#homeBanner` / 设置屏 / ② 的空与浮窗。
影子跟读的暗色 token 在 `app/index.html` 里都在（`#1c1a17` 暖黑、`--muted` 等）—— 照着写一套覆盖，别新造色。

**锁**：E2E 切到 `body.dark` 后断言外壳关键元素的背景/文字色**不是浅色那套**（取 computed style 比色值）。

## W3 · 答题对错的 `aria-live` 播报（PRD §10.4）

② 答题后「对了 / 正确的那一个是 X」现在没有 `aria-live`（全页只有 `#abToast`、`#syncHint` 有）。
**要求**：让对错反馈被读屏播报（`role="status"` 或 `aria-live="polite"`，别用 `assertive` 打断朗读）。
**锁**：断言承载反馈的节点带正确的 aria 属性。

## W4 · 拆掉 `buildQueue` 里那条死分支（M2 风险）

`app/index.html` 的 `buildQueue()` 里新增的 `inScope` 闸是**死代码**，且对非首篇会算出 0 句新句（新句窗口仍按全局数组索引 `[startNew, endNew)`）。
**要求**：**拆掉或重写**，不要留着 —— 下一个 agent 很容易在它上面加逻辑。既然任务模式的队列由 `syncQueueFromPlan`（走引擎的 `scope`）决定，`buildQueue` 里跟「新句窗口」有关的那段要么删、要么让它也按 `scope` 算。
**锁**：断言「进第 2 篇时 `buildQueue()` 不产生 0 句的新句窗口」或等价不变式（若你判断该函数整体可删，就删掉并断言没有调用方）。

## W6 · PWA（PRD §2.5）

影子跟读**没有** service worker，主站有。3.0 要继承的是主站那一套：把 manifest + service worker 搬到 `/app/`（或让 `/app/` 复用主站的）。
注意构建白名单（`scripts/build_site.mjs`）—— 新增的运行时要抓的文件必须加进去，否则构建自检会失败。
**锁**：断言 `/app/` 里有 manifest 链接；service worker 的注册不报错（能在测试里 stub 掉注册也可以，但要说清测了什么）。

## W8 · 任务条 ① 的「一辈子读过」口径 —— 先判断再动

任务条 `① 通读 n/N` 的分子是「该篇每句至少读过一次（lifetime）」，副行「还剩」也是 lifetime。
复审认为「与卡片一致、可辩护」。**要求**：你读一遍 §9.3/§9.4 后给出判断 —— 若认为该改成"今天读过"，改并写清；若认为 lifetime 才对，在报告里说明理由并加一条注释，别默默放着。
