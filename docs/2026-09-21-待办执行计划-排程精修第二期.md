## 1. 顶栏收纳「修到底」（阻塞推送，先做这个）

> **2026-09-21 本轮结果**：三层原因里两层被压测台否掉（口径/时机都不是这条红的成因），
> 真因是**用例往应用自己会重建的节点里写长文字**（`loadVoices()` 在 `document.fonts.ready` /
> `voiceschanged` / 云端会话恢复三处整体重建 `#voiceSel`）→ 改成用窗口宽度造"放不下"；
> 产品侧只留一条有依据的修复：`fade-nav` 移出守卫（它只改透明度）。
> 下面三步保留原文，供复盘「上一轮为什么失败」。


**已实测的三层原因**（数字都是量出来的，不要重新猜）：

1. 「放得下」= 只看有没有折行。长标签把 `.topbar` 撑到比屏幕宽时它**不折行**，宁可让整页横向滚 → 恒判"放得下"。
   实测：屏幕 1280，`.topbar` 实测 **1504px**，`nav-menu` 不挂、`#btnMenu` `display:none`。另一次：`clientWidth=1272 / scrollWidth=1350`。
2. 「滚动中不测量」的守卫读 `body.scrolled`，而该 class 由滚动监听在**下一个 rAF** 才挂 → ResizeObserver 抢在同一帧进来就量到收缩态（标题字号被压小 → 真的放得下 → 把刚挂上的 `nav-menu` 摘掉）。
3. 把图标字体改成非阻塞后，收纳开始**等第三方 CDN 字体**（4 秒内没落地就不收）。已退回阻塞加载。

**为什么上一轮失败**：在没有压测台的情况下连改三版，靠"跑一次看绿不绿"判断。单跑 `--repeat-each=12` 能 50/50 绿，一进 4-worker 全量就间歇红。

**下一步（照这个顺序）**：

1. 写压测台 `work/nav_probe.mjs`（或 Playwright 脚本）：同一条用例**并行 24–32 次**，每次记录
   `{innerWidth, bar.clientWidth, bar.scrollWidth, 是否折行(contentH vs tallest), scrollY, body.class, 每次 syncNavMode 的结论序列}`。
   结论只有两个分布要看：**判"放得下"的次数占比**、以及**先挂上又摘掉的次数**。
2. 用分布区分「测量时机」与「测量口径」：
   - 若失败样本里 `contentH == tallest`（从未折行）→ 是**口径**问题，必须在 `navRowWraps()` 补横向溢出判定；
   - 若 `nav-menu` 挂了又被摘 → 是**时机**问题，守卫要改读底层事实（`window.scrollY > 60`，与 `.scrolled` 同阈值）并让 `nav-measure` 期间解除收缩压扁。
   上一轮两处我都单独试过，各自都让一部分用例变绿、又让另一部分变红 —— **说明很可能两者都要，且要同时改**，这次必须一次改齐再用压测台验证，不要分两次试。
3. 门禁：`npm test` **连绿 5 轮**（改测试或 conventions 就清零重跑）。
4. 图标字体挪出关键路径（首屏 3–5 倍，因果已被 8 次复现证明）**等顶栏不再依赖远端字体之后再拿**：
   给图标钮预留固定宽高（或把常用几个图标内联成 SVG），让测量与字体到达无关。

**注意**：这是分支最新那笔「顶栏只允许一行」改动自带的洞，不是新引入的功能；`body.scrolled .topbar-right { max-width:0 }` 那套压扁规则和 `body.nav-menu` 那套面板规则是同一问题的两面，改一边会碰另一边。
