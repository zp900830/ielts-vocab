# 任务模式底栏排查（2026-09-21）

他报的两件事：①「说好的隐藏播放条、保留底部通栏的任务条，一直没改」②「功能上也有些问题」。
下面每条都是**在浏览器里量出来的**（本地 8931，Chromium，390×844 与 1200×762 两档），不是读代码猜的。

## 结论先说

他没记错。**已批准的原型要求任务模式底部只有一条通栏任务条 +（① 态）一条极窄播放行**；
实际上线的是**整条播放条原封不动留着**，只删掉了「下一句」和「语速」两颗，于是变成三层堆叠。
偏差被一行代码注释记录成了"他拍板播放条不藏"，但**这句话在 docs/ 里没有任何出处** ——
它只存在于 `shadow/index.html:1175` 的注释和 `playwright-tests/journeys/shadow/task-flow.spec.ts:42` 的注释里，
是 agent 写的，不是他说的。

原型真值：`docs/prototype/2026-09-20-任务模式原型.html:248-253`（① 通读）、`:283-284`（② 挖空）、`:382`（③ 选义）
规格真值：`docs/2026-09-20-学习计划与任务模式重设计-PRD.md:381-397`（§10.1 一条任务栏，三种态换内容）
现行口径（与上面冲突）：`docs/PRD.md:542`

## 实测：底部吃掉多少屏

| 态 | 播放条 | 任务条 | 做题卡 | 底部合计 | 占 844 高 |
|---|---|---|---|---|---|
| ① 通读（展开态） | 88px | 61px | — | **157px** | **18.6%** |
| ② 挖空 / ③ 选义 | 88px | 61px | 223px（top=459） | **385px** | **45.6%** |

原型口径下 ② ③ 应该是 **57px（只剩任务条）**，① 应该是 **约 91px（任务条 + 窄播放行）**。
`docs/2026-09-18-产品整改清单.md:452` 那条 P1「移动端底部双栏 …实测吃掉约 18% 屏高」**到今天还是 `[ ]` 未勾选**，
量出来的 18.6% 与它当时写的 18% 对得上 —— 确实一天都没改过。

## 六条缺陷（逐条可复现）

1. **② ③ 做题态整条播放条还在**。原型要求这两态底部只有任务条（`:283`、`:382`）。
   实测 `.loop-wrap` / `.ab-wrap` 被 `quiz-mode` 藏了，但 `.ab-left`（上一句 / 播放 / 收起）和进度行还占 88px，
   把做题卡顶到 top=459 —— 手机上快半屏不能读原文。
2. **「上一句」和「下一句」被拆到两条栏**。① 态：上一句在播放条（top=656），下一句在任务条（top=718），
   两颗相隔 62px、分属两条不同颜色的栏。原型 `:250` 明确把两颗放在**同一条**通栏右侧。
   这是"翻句"这个最高频动作，肌肉记忆每次要换一次落点。
3. **「回看句子」同时存在两颗**（② ③ 态）：做题卡里一颗、任务条上一颗，同名同动作同屏。实测 `dupBtn: ["回看句子"]`。
4. **进度数字「1/24」说两遍**（② ③ 态）：做题卡头 `② 挖空填空 1/24` + 任务条 `② 挖空 1/24`。
   实测 `dupNum: ["1/24"]`。**直接违反 §10.1 自己的数字唯一性表**（今日进度唯一的家是任务栏）。
   现有用例 `task-flow.spec.ts:58` 只对比了任务条与 `abTitle`，没把做题卡算进去，所以漏网。
5. **语速在任务模式里彻底改不了**。`shadow/index.html:1178` `body.task-mode .audiobar .rate-wrap { display:none }`，
   实测 `display:"none"`，全页再无第二个倍速入口。影子跟读里 1.25×/1.5× 是核心用法，这条是**功能丢失**不是美观问题。
6. **任务条上没有「退出」**。§10.1 ① 态控件表里写了「退出」，实测 `exitBtnOnBar:false`。
   `TASK.exitTaskMode()` 唯一入口在今天面板里（`shadow/index.html:5327`），
   而手机上顶栏已收进汉堡 → 退出要 汉堡 → 今日 → 退出任务模式 三跳。

## 顺带量到：收起播放条不是出路

点「收起」后变 40px 小胶囊，仍浮在任务条上方（109px / 12.9%），且胶囊里还是
上一句 / 播放 / 循环 / AB / 书签 五颗 —— 与任务条的「再来 / 下一句」继续撞。
所以「让他自己收起」不能替代按原型重排。

## 归位建议（原型已给出，不需要新发明）

| 控件 | 现状 | 原型口径 |
|---|---|---|
| 上一句 / 下一句 | 拆在两条栏 | 同一条通栏右侧（①） |
| 播放 / 暂停 | 播放条 | ① 态窄播放行左侧 ▶ |
| 单句循环次数 / A-B | 播放条 | ① 态窄播放行（循环本句 / A-B） |
| 语速 | **任务模式里被藏掉** | 原型未画 → 需决定（建议进窄播放行） |
| 书签 | 播放条 | 原型未画；顶栏菜单里本来就有「记下当前位置」，不算丢 |
| 进度条（整句拖动） | 播放条 | 原型未画 → 逐句任务态下不需要，建议随播放条一起收 |
| 退出任务模式 | 仅面板内 | §10.1 要求常驻条上 |
| ② ③ 的播放条 | 88px 还在 | **整条不要**，只留任务条 |
