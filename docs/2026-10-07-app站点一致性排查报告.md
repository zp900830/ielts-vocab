## A. 文字语义 / 术语一致性

### A1 【高】同一个「位置」有 6 种排法，其中一种第二个数没有单位

| 出处 | 现在写的 | |

| `app/index.html:4933` | `5 / 40` | 同一个 `paint()` 的 else 分支（取不到文章序号时），相隔两行，连「第」和单位都没了 |

### A2 【高】「章」在 app 里同时指两级 —— 章和篇

`app/index.html:4931`、`3528`、`5363` 三处把**文章序号**（`ai = artOfSent[...]`）印成「**第 N 章**」；
而 `app/index.html:6052` 的 `chapterOfGlobal(i)` 用的是**真的章节层级**（`computeChapterStart`，`3378`），也叫「第 N 章」。
同一个字在同一个文件里指两个不同的数据级别，而这两级在 UI 其它地方叫「**篇**」（`本篇`、`第 ${a+1}/${SECTIONS.length} 篇`）。

用户看到的是：正文头部「第 3 章 5/40」，任务条同一篇却写「第 2/6 篇」。
改动面：3 处字符串（把 `artOfSent` 那三处改成「篇」），零逻辑风险。**这条比上一版任何一条都值得先做。**

## B. 样式 token 一致性

先给实测统计（口径：`app/index.html` + `app/app.js` 两个文件，不含其它站点）：

- `font-size` **26 档 / 321 条 px 声明**（另有 12 条 `font-size:0` 的纯图标重置）。整数 9–24 几乎全勤，另有 **8 个小数档**：`10.5 / 11.5 / 12.5 / 13.5 / 14.5 / 15.5 / 17.5 / 18.5`；其中 `14.5 / 17.5 / 18.5` 各只用过 1 次、`15.5` 用过 2 次。`12px` 55 次 vs `12.5px` 24 次 —— 这 79 条其实是同一档。
- `backdrop-filter: blur()` **65 处字面量 / 10 个档**（8/10/14/16/18/20/22/24/28/32），另有 `var(--iel-blur)` 8 处、`var(--blur, …)` 4 处。
- `box-shadow` **57 种写法 / 102 条声明**。
- 硬编码色 **249 处 hex（81 个不同值）+ 362 处 rgba**；`#33302b`（深色描边）写死 **30 次**，而它明明有 token。
- 缓动：`cubic-bezier(.22,.61,.36,1)` 手写 **29 次**、`(.32,.72,.35,1)` 5 次 —— 这两条**用得最多的曲线恰恰没有 token**；已 token 化的只有两条，且各自只服务一个场景：`--ease-smooth (.32,.72,.24,1)`（`app/index.html:72`，引用 19 次）与 `--ease-bar (.32,.9,.28,1)`（`73`，引用 28 次）。合起来 = 全站 4 条曲线、两套 token 两套字面量。
- `transition` 时长：0.5s 以下实测 **21 个档**（`.04 .05 .06 .08 .1 .12 .14 .15 .16 .18 .2 .22 .25 .26 .28 .3 .32 .34 .38 .4 .45`），其中只有 `.45s`/`.32s` 被 token 化（`--t-morph`/`--t-bar`），其余 19 档全是字面量。
- 圆角：`999px` 63 次、`10px` 20 次、`50%` 19 次、`16px` 18 次，10–24px 之间还有 **9 个档**（10/11/12/14/16/18/20/22/24）。
- `:hover` 112 处、`:active` **12 处**、`:focus-visible` 9 处。
- `body.dark` 相关声明 **171 行 / 196 处** —— 成对写得很勤，**没有发现漏配深色导致亮斑**，这点是干净的。

### B1 【高】`.fav-badge` 绕过了它自己的 token

`app/index.html:47` 定义了 `--note-bg: #fdf1dc; --note-text: #8a5f0a`，注释还写明「沿用既有的 `.reader-head .fav-badge` 用色」；
`app/index.html:1872` 却仍是 `background: #fdf1dc; color: #8a5f0a;` 字面量。**同两个色，一个有 token 一个没有** —— 以后调 token，徽章不跟着变。
改动面：1 行，零风险。

### B2 【高】两处小字用 `--coral-deep`，而这个值在同一个文件里已被判定不合格

`app/index.html:672`、`678` 用 `color: var(--coral-deep, #c0492f)` —— token 一定存在，fallback 是死代码；
`--coral-deep` 实际是 `#c9564a`（`app/index.html:42`），而 `app/index.html:1759` 的 AA 注释已经写明「`--coral-deep #c9564a` 压白只有 4.27:1（11.5px 正文要 4.5）」，并因此**故意**在 `1757` 硬写 `color: #c0492f`。
也就是说：同一个「危险动作红」，一处按 AA 收深了，另外两处还在用 4.27:1 的 token 刷 11–12px 小字（`.ab-menu-action.danger`、`.ab-loop-item .ab-loop-act.del` —— 恰好都是「删除」这类破坏性动作）。
改动面：2 处（换成同一个达标色，或给 token 分「大字/小字」两档）。

### B3 【高】同一件事三个来源，其中一个 token **从来没有被定义过**

玻璃模糊在 app 里有三条写法，互不相认：

| 写法 | 次数 | 出处 | 状态 |
|---|---|---|---|
| `var(--iel-blur)` | 8 | 定义在 `app/index.html:76` = `blur(22px) saturate(170%)` | ✅ 真 token |
| `var(--blur, blur(22px)) saturate(170%)` | 4（`1291`、`1649`） | **全文件搜不到 `--blur:` 的定义** | ❌ 永远走 fallback；`--blur` 是个不存在的名 |
| 字面量 `blur(Npx)` | 65（10 个档） | 如 `.audiobar` 用 `blur(32px) saturate(180%) brightness(1.02)` | 游离 |

顺带同一个毛病在底色上又出现一次：`var(--glass-strong, rgba(255,255,255,.97))`（`1291`、`1649`）—— token 是有定义的（`68` = `rgba(252,250,246,.96)`），但**那个 fallback 写的是另一个颜色**，读代码的人会以为浅底是纯白。

## D. 交互一致性

浮层显隐目前**三套实现并存**：inline `style.display`（`openModal`/`closeModal`，`app/index.html:5514`/`5530`）、`.open` class（5 个 wrap + `#lcDrawer`，`classList` 开关相关共 31 处）、`hidden` 属性（`#mePop`、`#todayPanel`、`#blankPop`、`#voicePop`、`#passCard`）。
下面 6 条高优先级里，D1/D2/D3/D4 四条都是这个混用直接造成的 —— 它们不是四个独立问题，是同一个问题的四张脸。

### D1 【高】词库抽屉的锁滚会永久残留（同一个 class 挂在两个不同宿主上）

`togglePanel`（`app/index.html:5682-5691`）：移动端把 `panel-open` 挂在 **`.layout`** 上并写 `document.body.style.overflow='hidden'`（`5687-5688`），桌面端把**同名 class** 挂在 **`body`** 上（`5690`）。
CSS 也分成两套认这两个宿主（`817` `body.panel-open aside` 在 `min-width:701` 块里；`1147` `.layout.panel-open aside` 在 `max-width:700` 块里）。
于是：手机开着抽屉 → 转横屏 / 把窗口拖宽过 700px → `panel-open` 还在 `.layout` 上，桌面那套不认它；
而全文件 `document.body.style.overflow` **只有 5688 这一处写入**，唯一会清它的路径是 `togglePanel` 的移动端分支（要求 `matchMedia('(max-width:700px)')` 仍成立）和遮罩点击（`5600`，同样要求窄屏）——
此时都不成立 → **页面永久锁滚，只能刷新**。
改动面：1 个函数（锁滚收进一个「无条件清」的出口 + class 只挂一个宿主）。

### D2 【高】☁ 云同步浮层有两套显隐机制，**两条打开路径各自只关得掉自己那一种**

同一个 `#cloudWrap`：

| 谁打开 | 用什么 | 谁能关 |
|---|---|---|
| `toggleCloudWrap`（`app/index.html:4154-4161`） | `.open` class | 它自己挂的 `pointerdown`（`4159`）+ `closeAllOverlays` 摘 class（`5550`）+ `openModal` 互斥摘 class（`5520`） |
| 云端未连通的提示（`app/index.html:4663-4664`） | inline `style.display='block'` | **只有**全局 click 里那条 `if (_cp.style.display === 'block') closeModal(_cp)`（`5590-5591`） |

后果三条，都是同一件事的不同面：
1. 用 inline 打开之后按 **Esc**：`closeAllOverlays` 只摘 class（`5541` 的 `OVERLAY_WRAP_IDS`），它看不上 inline，于是**函数返回 `true`（「我关掉一层了」）而屏幕上那一层还开着** —— 后面的 `listenCollapse` 分层判断也被这次假成功吃掉。
2. 用 class 打开之后点外面走 `5590` 那条：`display !== 'block'`，不关（靠 4159 那颗一次性监听补上，而那棵树是脆的，见 D11）。
3. `syncToggleAria`（`5566`，cloudWrap 那一行在 `5573`）按 class 反推 `aria-expanded` —— inline 开着而 class 没上时，读屏报的是「收起」。

`markWrap / abWrap / loopWrap / rateWrap` 四家走的是同一份 class 代码路径，只有 `cloudWrap` 有第二条 inline 路。
改动面：删掉 `4663-4664` 那条 inline 路（改成调 `toggleCloudWrap`），统一到 class。`closeModal/openModal` 那套继续留给真正的 `#pop`/`#jumpPop`/`#loginModal`。

`_trapFocus()`（`app/index.html:5502`）写好了，只在 `openModal`（`5526`）里挂 —— 走这条路的是 `#pop`、`#jumpPop`、`#loginModal`。

| `#todayPanel`(`2938`) | `role=dialog aria-modal=true` | `hidden` + `.open` | ❌ | ❌ |
| `#lcDrawer`(`app/app.js:653`) | `role=dialog aria-modal=true` | `.open` | ❌ | ❌ |
| `#mePop`(`2798`) | `role=dialog`，`aria-modal` 打开时才补（`app/app.js:1345`） | `hidden` | ❌ | ✅（`app/app.js:1351` 主动 focus） |

   而那颗 `e.stopPropagation()` 本身就是无效件 —— 两个监听挂在**同一个 `document`** 上，`stopPropagation` 拦不住同一目标上的另一个监听器（要 `stopImmediatePropagation`），何况它还是后跑的那个。
   （这条是读代码 + 脚本注册顺序推出来的，**没在真机上敲过键盘**；做的时候我会先写一条 Playwright 敲 Esc、断言两层状态，再改。）
