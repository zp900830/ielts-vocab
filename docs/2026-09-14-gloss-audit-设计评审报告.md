## 二、逐条展开

### 🔴 1. `node --check shadow/index.html` 跑不通

实测（Node v22.22.2）：

```
$ node --check shadow/index.html
TypeError [ERR_UNKNOWN_FILE_EXTENSION]: Unknown file extension ".html"
```

Node 从不接受 `.html`。这条命令在历史上很可能是"以为通过"而非真通过。
**建议改为**：抽出内联 `<script>` 内容到临时 `.js`，再 `node --check`；或直接把它列为一步工具脚本（可幂等重跑）。否则第 5 节的提交门槛是空的。

### 🔴 2. 数据会被构建器整体冲掉 —— 「无脚本再生成」是不成立的假设

`build_ielts.py` 的关键三行：

```python
OUT = ".../雅思影子跟读.html"
pat = re.compile(r"const SECTIONS = .*?;\nconst VOCAB = .*?;\n(?:const CHAPTERS = .*?;\n)?", re.S)
pat.sub(lambda m: new_block, html, count=1)
```

而 `shadow/index.html` 的内联注释自己写着：**`/* ===== 数据（由构建器生成） ===== */`**，且第 3–5 行正是 `SECTIONS / VOCAB / CHAPTERS` 连排 —— 完全命中 `pat`。

更要命的是：构建器生成的 `sections_js`（第 121–124 行）只有 `title / paragraphs / zh / words`，**没有 `sentZh`，也没有 `paraZh`**。

> 也就是说，一旦有人重跑构建（或改了 OUT 指向 shadow），**1809 条句译 + 308 条段译 + 3219 条 m 的人工校对成果会一次性归零**，且页面会退回无译文状态。

稳妥做法是先把这项几十小时量级的人工产出挪出危险区（备份 / 构建器保留 sentZh / 显式冻结），再开始改数据。文档目前完全没有这条风险评估。

### 🔴 3. 第三份数据副本已漂移 673 条

三份 VOCAB 同为 3219 条 key（完全对齐），但释义已有实质分歧：

| 词 | `shadow/index.html` | `雅思影子跟读.html` |
|---|---|---|
| smog | n. 雾霾 | n. 烟雾 |
| oasis | n. 沙漠绿洲 | n.（沙漠中的）绿洲 |
| el nino | phrase. 厄尔尼诺 | phrase. 厄尔尼诺现象（太平洋赤道地区海水异常变暖的现象） |
| gust | 压平成单行 | 保留换行分段的多行释义 |
| **合计不一致** | — | **673 条** |

legacy 副本反而保留了更完整的释义。文档若不同步这份文件，改完会出现"两个页面两套词义"。

### 🔴 4. R2 必踩的数据雷：393 条 `；；`

```
avalanche      => "n. 雪崩；；n. 纷至沓来"
plain          => "n. 平原；；adj. 简单明了的；朴素的"
arctic         => "adj. 北极的；；n. 北极地区"
mediterranean  => "n. 地中海；；adj. 地中海的"
upgrade        => "v. 提升；提高；改进；；n. 增加；改进"
```

按 R2 的 `split(/[；;]/)` 取前两项，第 2 项是空串 → 行内显示 **`n. 雪崩；`**（悬空分号）。这比现在的"只显示首义"更难看。
**必须先做数据清洗**（去掉连续分隔符 + 去空段），并把它作为 R2 的前置步骤写进文档。

### 🔴 5. 现有 E2E 拦不住上述 bug

`tests/e2e/shadow/inline-gloss.md` 第 3 步只断言：

> Verify: Length ≤ 12 characters (the `slice(0,12)` behavior)

`n. 雪崩；` 长度 6，**照样通过**。现有测试不但保护不了，还会把脏数据放行到 CI 绿。
§4 的新断言至少要包含：① 含两个义项分隔符；② **不以 `；/` 结尾**；③ 拼接后无空义项。

### 🔴 6. R2 有 9.1% 改了反而更糟，且无降级策略

实测 3219 条：

- 首义本身超 12 字的：**0 条**（现在每条都完整显示首义）
- 前两义拼接后超 12 字的：**293 条，9.1%**

这批词改后会从「首义完整」退化成「首义完整 + 第二义被切一半」：

```
destructive | adj. 破坏的；毁灭性的   => adj. 破坏的；毁灭性…
horizon     | n. 地平线；思想等的范围；眼界 => n. 地平线；思想等的范…
endanger    | v. 使遭危险或伤害；危害；危及 => v. 使遭危险或伤害；危…
```

文档只写"超长仍截断"，没定义这两种策略选哪个。建议在 R2 里写明降级规则（推荐：**超长则退回只显示首义**，保证不做半截Second义），或把 12 字上限一并调整（注意 `.gl { white-space: nowrap }` 是这个上限的布局根因，放宽字数要同时改这条 CSS）。

### 🟡 7. R3 敏感词表举例失当

文档举例 `swear at、claim、make、take、get 等`。实测：

```
make=false  take=false  get=false  put=false  claim=true   ← make/take/get/put 根本不在 VOCAB
```

文中只对词表内的词打 `[[word:form]]` 标注，这几个虚化动词不在词表 → **永远不会被标注，脚本抽不出任何句子**。把 20 个高频动词全列上，全量 1809 句**只命中 6 句（0.3%）**。

### 🟡 8. 范围与手段矛盾

- 多义词：2209/3219 = **68.6%**
- 含至少一个多义标注词的句子：**1502/1809 = 83.0%**
- §2 承诺"全量 sentZh 句译（6 大章，按条全扫）"，§3 却只按敏感表重翻

建议把筛选条件从"敏感词表"换成客观可算的条件：**该句是否含多义标注词** → 1502 句。或者直接承认只做抽样修正，改 §2 的说法。

补一个有用的约束：语料按"一词一句"生成且跨句去重，**每个词在全文只标注一次**。所以工作量是收敛的：**3219 次义项选择 + 至多 1502 句译文复核**，可估算、可分批。文档没给这个数字。

### 🟡 9. `vocab.json` 不能当上游 —— 是它丢义

`vocab.json` 是 22 章 3254 条（跨章重复，去重后 3219）。与 shadow 对比：**312 条 m 不一致**，且多数是 json 侧丢首义：

| 词 | shadow | vocab.json |
|---|---|---|
| avalanche | n. 雪崩；；n. 纷至沓来 | n. 纷至沓来（**丢了「雪崩」**） |
| mop | n. 拖把；n. 乱蓬蓬的头发 | n. 乱蓬蓬的头发（**丢了「拖把」**） |
| sponge | n. 海绵；海绵动物 | n. 海绵动物（**丢了「海绵」**） |
| tap | n. 水龙头；轻拍；…；v. 利用 | v. 利用；；n. 水龙头；…（**义项顺序被打乱**） |

若按文档"以上游 json 为准回灌"，会把丢义固化。**同步方向必须反过来：shadow 为准，覆盖 json。**

### 🟡 10. §1 自相矛盾：既说「数据没错」又说「数据缺义」

实测是第三种情况 —— **有全义，但脏**：

- 含连续分隔符 `；；`：**393 条**
- 义项 >3 个（违反 R1「2–3 义为限」）：**455 条**（分布：4 义 260 / 5 义 110 / 6 义 50 / 7 义 20 / 8 义 11 / 9 义 3 / 10 义 1）
- 释义里混英文片段：**48 条**（`"flood"的现在分词`、`phrase.` 前缀的 `carbon dioxide` / `el nino`）

## 三、核对无误的部分（可放心依赖）

| 文档说法 | 实测 | 结论 |
|---|---|---|
| `will not swear at the heavy traffic` 被译成"…也不会对拥堵交通发誓抱怨" | ✅ 原文实句：`Leo will not [[curse:curse]] the bad luck and will not [[swear:swear]] at the heavy traffic.`；原句译完全一致 | 准确 |
| `swear` 的 m 并列两义 `v. 发誓；咒骂` | ✅ | 准确 |
| `glossParts` 只取首义截 12 字 | ✅ 第 23 行 `info.m.split(/[；;]/)[0].trim().slice(0, 12)` | 准确 |
| 6 大章 | ✅ SECTIONS = 6，句数 336/310/230/388/214/331 = **1809** | 准确 |
| 3219 词条 | ✅ 三份数据源均 3219（vocab.json 去重后） | 准确 |
| paraZh 段译 308 段 | ✅ | 准确 |
| 全部 sentZh 句译齐全无缺口 | ✅ 1809 句 0 缺失 | 准确 |
| `node --check` 可直接跑 | ❌ 报 Unknown file extension ".html" | 见 P0-1 |
| E2E 跑的是 shadow | ✅ `webServer: python3 -m http.server 8931 --directory ../shadow` | 准确 |

**顺带一条补强你背景分析的证据**：同一句里 `curse` 译对了（"咒骂"），只有 `swear` 译错（"发誓"）。说明这不是全局机器腔，而是**个别词的义项选择错误** —— 支持"定点修正"而非"重翻全文"的路线。

## 四、建议的修订清单（按实现顺序）

1. **先把风险堵上**：备份 `shadow/index.html`（像 2026-09-09 那样留 xxx.backup 时间戳），并在文档中写明"禁止在本期内重跑 `build_ielts.py`" / 或给构建器加保留 sentZh 的逻辑。
2. **数据先行**：清洗 393 条 `；；` 与 48 条混英文释义 → 输出清洗 diff 单独一轮，和实现分开验收。
3. **明确同步方向**：`shadow` 为准，回写 `vocab.json` 的 312 条差异；声明 `雅思影子跟读.html` 的 673 条漂移如何处理（建议同步或明确定其为废弃副本）。
4. **R2 定降级策略**：超 12 字退回单义；同时处理 `.gl { white-space: nowrap }`。
5. **R3 换筛选条件**：以"含多义标注词"为客观条件（1502 句），敏感词表作为排序优先级而非唯一入口。
6. **修 E2E**：断言加"不以分隔符结尾/无空义项"；`node --check` 改为抽 script 后校验。
7. **补工作量与分批**：3219 次义项判定 + 455 条 R1 收敛 + 1502 句复核，建议按章分批出 diff。
8. **改文案**：`tái` → 再/重生成；`VOCAB[*].m` → `VOCAB[词].m`（对象）；不碰清单去掉重复的 ex；17 → 18 个 test()。
