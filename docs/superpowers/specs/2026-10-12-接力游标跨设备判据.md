# 接力游标：跨设备当天一致（2026-10-12 晚）

他原话（逐字）：

> 为什么我换了台电脑任务的开始线又变了。我今天早上读还是在第三章第一句。晚上就变成我上午读到的
> 位置成今天任务的开始句了，这是什么情况。我感觉这块的逻辑也是反反复复好多 bug，
> 是否可以好好帮我排查修复一下。

（截图：正文里「今天任务 · 开始」线落在「Grandma announced her plan for the erection of a small
new dining room inside the old hall…」之前）

## 现象

- 早上在 **A 机**：今日任务开始线在**第三章第一句**；从那里读了一段。
- 晚上在 **B 机**：开始线跑到了「**上午在 A 机读到的位置**」。

## 根因：重算游标的判据把「今天读的句」也算进了接力

`manualStartToday()` 里，本机当天还没算过游标时（`resolvedDay !== 今天`）会做一次「接力重算」：

```js
let far = m.gi - 1;
for (let i = m.gi; i < len; i++) {
  const s = ss[i];
  if (s && (s.lastReadAt || 0) > (m.ts || 0)) far = i;   // ← 病灶：只看「晚于起点设定时刻」
}
cursor = far + 1;
```

判据是「`lastReadAt > ts`（起点设定时刻之后读过）」——**不区分「今天读的」和「昨天读的」**。

**为什么本机看不出来、换机就炸**：

| | A 机（早上） | B 机（晚上，云端重放后） |
|---|---|---|
| 起点账 | `{gi: 第三章句1, ts: 早上}` | 同上，但 **`applyDaystartEvents` 落账不带 `resolvedDay`** |
| 当天第一次读游标 | `resolvedDay` 已冻结 → 直接用 | 判据为真 → **重算** |
| 重算看到什么 | ——（不需重算） | 接触账里**已含上午在 A 机读的句** → `lastReadAt > ts` 命中 → `far = 上午最后读的句` |
| 结果 | 起点 = 第三章句1 | 起点 = **上午读到的位置 + 1** |

A 机靠 `resolvedDay`（当天冻结）挡住了，B 机因为重放不带这个字段而重算 —— 两台设备对**同一份账**
算出两个数，正是报障现象。

## 为什么这族问题「反反复复」

「今天从哪开始」这一个概念，实际有 **3 个时间态**（今天的起点 / 接力游标 / 存档位置）×
**3 个空间态**（本机 / 云端 / 另一台设备），每个入口各读其中一个组合：

| 报障时间 | 现象 | 直接原因 |
|---|---|---|
| 2026-09-26 | 「记住进度」 | 横幅没读存档位置 |
| 2026-09-28 | 已读句不恢复、第一下点跳走 | 恢复判据与队列不同源 |
| 2026-09-30 | 手动起点与队列/回显对不上 | 三处各算起点 |
| 2026-10-09 | 桌面设了起点，手机还是第一篇第一句 | daystart 事件没上云 |
| 2026-10-10 | 随身听把 currentArticle 钉成篇 1 | 入口自设上下文 |
| 2026-10-12 早 | 「继续学」跳到篇 1 第一句 | 横幅只用 nextArticle()，不看今日信号 |
| **2026-10-12 晚（本次）** | **换电脑后开始线跑到今天读到的位置** | **重算判据含「今天读的」** |

**本次的修法思路是「消除时机依赖」**：让重算结果**只依赖「今天以前的账」**，
与「什么时候算」无关（本机早算、B 机晚算、重算多少次，都得同一个数）—— idempotent。

## 修法

```js
const today = day2();
for (let i = m.gi; i < len; i++) {
  const s = ss[i];
  // 只认「今天以前」的阅读：接力 = 接着上次学到的位置；今天读的句不参与
  if (s && (s.lastReadAt || 0) > 0 &&
      ShadowPlan.dayKey(s.lastReadAt, bdHour()) < today) far = i;
}
```

- 昨天（或更早）读的 → 计入 → 接力照旧 ✓
- **今天**读的 → 不计入 → 今天的起点今天不漂 ✓
- 两台设备同一天 → 都基于「今天以前的账」→ **同一个数**（这才兑现了原注释里
  「接触账已云同步，两台设备推出来同一个数」的设计意图）
- 用 `< today` 而不是 `!== today`：顺带挡住时钟异常的「未来日期」句
- 必须带 `lastReadAt > 0`：未读句的 `lastReadAt = 0`，日键会落在 1970 年（否则会被误判成「今天以前」）

**一处修、全链对**：游标的下游全部读同一个 `ms.gi` —— 开始线（`paintTodayRange`）、
今日队列（`todayPlan` 的按篇刷句分支）、随身听今日任务（`manualRange`）、
「继续学」目标篇（`resumeArticle`）。

## 已知边界

- 起点若**设在已经读过的句上**（少见）：「今天以前读的」会把起点之后已读的句算进去，
  可能比旧行为多推进一句。取舍：跨设备一致性优先。
- `atEnd`（刷到全文末尾）行为不变。
