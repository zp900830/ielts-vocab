# 设计：任务模式改两步制（删 ③，② 改「挖空选择」）

日期：2026-09-22　状态：**已拍板，待实现**
他原话：「任务模式需要去掉第三步，看单词选中文。第二步改为"挖空选择"，提供干扰项，选择正确的挖空单词，并通过提示确定唯一性。如果有不确定的站在用户的角度判断怎么选择，最后改完了都合到 main 上 push。」
另有一句动因很重要：「**完成一轮需要的时间太长了**」—— 这次改动本身就是为了让一轮变短。

## 1. 现在是什么样（三处真值，动手前核对行号）

- 任务条 / 面板上「② 挖空」「③ 选义」字样见 `updateTaskBar()`、`renderQuiz()` 的 `qz-tag`

**陷阱先说清**：`ok3` 是毕业的必要条件。把 ③ 删掉而不给 `ok3` 换信号源，就**没有任何词能毕业**，`estimateDays` 会一路跑到 1095 天封顶，界面上四处工期全变成"三年内到不了终点"。这条不是假设，是 `:69` 的直接后果。

## 2. 目标形态

任务模式两步：

1. **① 通读**（不变：念句子，不遮词、不弹选择）
2. **② 挖空选择**：句子中把**目标词**挖空，给 **4 个英文候选**，其中 3 个是同语义场、同词性的干扰项；题干下方给中文译文并**下划线标出这个位置的意思**，用来把答案锁成唯一一个。键盘 1–4 可答。

## 4. 实现要点

1. **优先复用 `meaningQuiz()`（`:417`）现有的四选一与干扰项机器**，不要新写一套出题器 —— 它已经在生成 4 个选项并返回 `{kind:'mc4zh', s, w, ...}`。② 要的是"选项是英文词、题干是挖空句"，那是它的镜像，改输入输出方向即可，**不要两份实现**（本仓库反复栽在这里）。
2. `assemble()` 里 `pass:3` 的 items 取消；每题预算相应下调（现在一句 = 句时 + ② + ③ 两题，改完只剩一题）。
3. `estimateDays` 的 `:336` 那行跟着简化：只有一个 pass，`kind` 恒为 `mc4zh`。
4. `shadow/index.html` 的 `renderQuiz()` / `advance()` / `passNumber()` / `updateTaskBar()` 里 ②③ 分支收成一支；任务条 ② 态文案由「② 挖空」改「② 挖空选择」，`qz-tag` 不复述题号（PRD 数字唯一性）。
5. 词本 / `stageOf` 的 `owned` 档语义不变（`ok>=1` 即"义项直连"）。
