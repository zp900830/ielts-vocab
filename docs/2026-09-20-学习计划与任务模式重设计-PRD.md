## 0. 一页纸（给学生看的说法）

现在这套东西记的是「你今天读了哪几句、每句读了几遍」。但你真正在背的是**单词**。
所以它回答不了你最该被回答的三个问题：

1. 这个词我到底会不会？——现在没有「词」这一级的状态，只有一堆句子计数器。
2. 我今天只有 15 分钟，该做什么？——现在「每天几分钟」这个输入只用来**显示**一行小字，不参与排任务。真正决定你今天量的，是「总天数」反推出的每天新句数。
3. 我断了五天，回来还有救吗？——现在所有到期句一次性堆回来，没有降级、没有兜底，只有「今日 0/214」这一记闷棍。

重做后变成一句话：**按分钟排词，句子只是词的容器。**

- 打开就说「今天 15 分钟：6 句、12 道题」，做完就是做完，不会欠。
- 每天三遍同一批句子：**通读**（只管读）→ **挖空填目标词**（遮的一定是那个要背的词，选项是「长得像、中文翻译一样、但其实会说错」的兄弟词）→ **看英文选中文**。
- 填错了不扣分，弹一张辨析表告诉你「mild = 天气不冷，moderate = 不过火（要求、价格、强度）」。
- **辨析只做目标词之间的事**：词表里没教的词（fog、haze、smoke 这类）不进辨析组，也不进选项；同义替换资料（PDF 那些等号表）不进场，它们只管卡上「同义词」那一栏。
- 卡片式「拿着词表背单词」这条路不做了：读句子本身就是背单词。
- 「连续天数」跟「今天做了多少」解耦：地板（3 句；当天有题就再加 3 题）就算活着，但面板会老实写「今天只是地板」。

## 1. 目标与非目标

### 1.1 目标（一期）
| # | 目标 | 验收口径 |
|---|---|---|
| G1 | 记忆模型长在词上 | 每个目标词有独立阶段与到期时间；面板能回答「我会多少个词」且数字同源 |
| G2 | 时间预算真的决定队列 | 选 10 分钟与 45 分钟，队列句子数不同且都能算完；断更多日不产生「还不完的今天」 |
| G3 | 三遍流程不中断跟读 | ① 遍全程零选择操作；②③ 遍成块 |
| G4 | 挖空只遮目标词，选项可证明唯一 | 未经裁决的词组不参与出题；出不干净自动降级为回忆题；「这题有问题」一键上报 |
| G5 | 辨析成为一等内容线 | 一期把课文里 220 组段内共现近义词全部辨析入库（成员一律目标词），出题资格随组数增长 |
| G6 | 进度不怕清缓存 | append-only 事件流上云，换设备/被 Safari 驱逐后可重放 |

### 1.2 非目标（明确不做）
- **不做口语评测**。他原话（2026-09-19）：「没有练口语这么一说，因为本来也不算是练口语很好的素材。主要目的就是背单词。」跟读只是记忆手段，不打分、不纠音。
- **不做卡片式词表背诵入口**。他原话：「我读句子也是为了背单词，而不是说只有拿卡片去背单词，那才叫背单词。」词卡只作为**答错后的解释层**与**词本查询**存在。
- 不做多人/分享/排行榜（只有他一人使用）。
- 不做主站复用（数据结构预留 `kind` 字段，代码不写主站分支）。
- 一期不换 FSRS 排程算法（见 §15 P2），但事件记录必须够它以后拟合。

## 2. 现状诊断（可复验的事实，不是感受）

代码集中在 `shadow/index.html` 的 `TASK` 模块（约 3911–4731 行）。

### 2.1 记账对象错了：句有曲线，词没有
- 排程单元是句子：`prog.sentences[全局句号] = {reps, phase, nextDue, lastRead}`（`recordRep` index.html:3993），间隔表 `INTERVALS=[0,0,0,1,1,2,2,3,3,4,5,5,5,5,5,7,7,7,7,7,14]`（:3913）按 `reps` 取档。
- 词一级**只有统计时的临时反查**：`renderStatsSection` 用正则从读过的句子里现捞 `[[词:...]]` 算「覆盖词汇」（:4517-4524）。也就是说「这个词我会不会」这一事实从未被存下来。
- 后果：1833 句 / 4072 个可点标记（= 每句平均 2.2 个目标词）。一句读 3 遍，究竟给谁记了功？系统答不出，UI 也就只能说「今日 12/45 句」。

### 2.2 「每天几分钟」是装饰品
- `newPerDay` 由总天数反推：`newPerDayOf(days) = ceil(总句数 / days)`（:4250）。
- `dailyMinutes` 只进 `planCapacity`（:4272）算「按这个轮数走完一天需要 X 分钟」「tight 警告」，**不参与今天装多少句**。`buildQueue`（:4045）里没有一处读 `dailyMinutes`。
- 「慢 / 正常 / 快」三档实际做的是 `newPerDay = floor(n/2)` 或 `ceil(n*1.5)`（:4565, :4613）——用乘法伪装强度控制，改完没人知道今天到底多少句。

### 2.3 队列只在开面板时现算，且只有一种单位
`buildQueue()` 在 `renderToday`（:4457）和 `enterTaskMode`（:4135）里各算一次；队列项只有 `{i, type:'new'|'review'}`。没有容量概念、没有降级策略、没有「今天装不下」的分支。

### 2.4 断更后没有出口
新句窗口已改成按「已开过的句子数」推进（:4052-4055 的注释记录了上一次修吞内容的坑），这一点是对的。但到期复习是**全量**扫进队列（:4068-4080），断一周就是几十句一起到期；唯一的手动出口是 `pauseNew()`「暂停新句」，一个只能减新句、不能减复习的开关。

### 2.5 「藏控件」式的假简洁
`body.task-mode .audiobar .ab-step { display: none; }`（:1094）——进任务模式就把「上一句 / 下一句」直接 CSS 隐藏。想回读刚才那句只能退出任务模式。这是「做得非常糟」最典型的体感来源。

### 2.6 同一个数字说三遍，且互相不打架才怪
- `taskBar`：`今日 done/total · 剩余 ~t`（:4333）
- 播放条标题 `abTitle`：`今日 done/total · 剩余 ~t`（:4349）**同一句话再说一遍**
- 面板：`已读/未读`（另一套 done 口径 :4468）、`预计剩余`、`当前循环 已完成 Y 轮`、`计划 X 轮`、`本轮 A/1833`
- 「轮」有三个不同源的量：`planCapacity().cycles`（预估）、`prog.cycleCount`（已完成）、`cycleSeen` 的 key 数（本轮进度）。三者定义互不相容，学生不可能理解为什么「计划 1.4 轮」而「已完成 2 轮」能同时成立。
- 更糟的是口径本身：`done = todayQueue.length - newLeft - reviewLeft`（:4323）而 `readCount` 另用 `reps>=3 && lastRead>=今天` 现算（:4337），两个 done 在边界条件下会不一致。

### 2.7 没有规格
`docs/PRD.md` §5 影子跟读只有 5.1–5.8（播放、音色、阅读辅助、词库抽屉、书签、进度与云同步、加载与错误），**学习计划与任务模式一字未提**。这块功能一直是「代码即规格」，所以每次改动都在猜，他每次用上手的不适都没有文档可以指。

### 2.8 数据只有一条腿
云同步只 upsert `{marks, pos}`（书签与播放位置，见 PRD §5.7），学习进度、计划、词状态**全在 localStorage**，面板里那句「进度不出本机，清缓存即归零，这是唯一的兜底」（:4500）就是现状的自我承认。iOS Safari 对未加到主屏的站点 7 天不访问会连 IndexedDB 一起驱逐。

## 3. 同类产品调研结论（借什么 / 避什么）

| 产品 | 借走的东西 | 留下的教训 |
|---|---|---|
| Anki | 新词有日上限、复习优先于新词；`leech`（反复出错的卡要被单独处置而不是继续循环） | 复习无上限 → 断假即雪崩；卡片脱离语境，复习变成「认卡不认词」 |
| FSRS（Anki 新算法） | 排程应基于复习历史拟合，**前提是事件记录足够全** | 一期不换算法，但记录格式按它将来能用来设计（§12） |
| 墨墨背单词 | 用「每天多少分钟」而不是「每天多少词」作为主输入；把「未复习积压」显式量出来 | 积压一旦显示，反而制造焦虑并诱发弃用 —— 本设计选择「不生成欠账」（P5）而不是「把债摆出来」 |
| 不背单词 / 欧路 | 填空题目从**真实语料例句**里出，而不是中文→英文默写 | 但它的选项常是随机词，考的是辨识而不是辨析 —— 我们要的是「长得像、翻译一样、用错会说不通」的兄弟词 |
| 每日英语听力 | 逐句跟读 + 倍速 + 循环的交互骨架（现有实现已具备） | 完全没有排程层，读完就忘，说明「只是跟读」不够 |
| Duolingo | streak 要有兜底（连胜冻结/练习补），否则断一次就整条弃用 | 但它把所有指标压成一个大数字 + 音效奖励，掩盖了「你到底会没会」——本设计禁止两栏合并（P6） |

**综合出的三条取向**：
1. 预算单位是**分钟**，不是句数也不是卡数；
2. 完成度的货币是**接触**，检索题只负责**晋升**（不卡完成度）；
3. 出题资格必须与**内容裁决**绑定 —— 没被人工/独立审核确认「不会多解」的词组，禁止出来当选项。宁可暂时只做回忆题，也不错题教错人。

|---|---|---|

| P2 | **接触是货币，检索只是升级考试**：① 遍完成就计今日进度；②③ 答错不扣进度，只留「未晋升」 | 他否掉「很多选择操作打断进度」后的推论 |

| P5 | **不生成欠账**：每天按今天的时间重算，昨天没做完不等于今天欠 | 三池 + 时间预算方案，他选「按今天有多少分钟装配」 |

| P7 | 一期只做跟读站，但队列项预留两种类型（`sent` / `word`） | 他选「只做跟读站，队列项预留两种类型」 |
| P8 | 内容必须有可回溯出处，禁止模型自由造词；低价值不是砍的理由，**只有「照抄会说错英语」才砍**；辨析内容同等适用 | 见记忆 `card-content-provenance-rules`（词卡管线已按此跑通两轮） |

| P10 | **辨析只针对目标词**：辨析组的成员、选项、辨析表里出现的词，一律必须是课文里被标出来的目标词。同义替换资料（何琼等号表、高频书同释义表）不作为辨析来源，那些词不进场 | 他 2026-09-20 连说两遍「只关注目标词」 |

## 5. 核心模型

### 5.1 词状态机（唯一的「我会不会」）

```
fresh ──────① 跟读 1 次──────▶ seen ──② 在两个语境各答对 1 次──▶ recognized ──③ 答对 1 次──▶ owned
 陌生                          已见面                            文中可辨                       义项直连
                                                                                 │
                                            reps ≥ 20 且最后一次 ③ 答对 ──────────┘
                                                                                 ▼
                                                                            graduated 已毕业
```

| 状态 | 学生视角 | 进入条件（全部可复算） |
|---|---|---|
| `fresh` | 没见过 | 初始 |
| `seen` 已见面 | 「这句我读过了，这个词我读到过」 | ① 遍把它所在句完整跟读 ≥1 次 |
| `recognized` 文中可辨 | 在语境里能挑对 | 在**两个不同语境**（该词的课文句 × 卡上 `ex` 例句）各答对 1 次 ② 题；同一语境重复答对不叠加 |
| `owned` 义项直连 | 看到词就知道这句里是什么意思 | 答对 1 次 ③ 题 |
| `graduated` 已毕业 | 不再占今天的位置 | `reps ≥ 20` 且最后一次 ③ 答对；此后只做低频抽查 |

**答错不降级，只缩短**：任何一次答错 → `due = 今天之内再见一次`，`err++`；`err ≥ 3` 标 `leech`（重点词），强制进入最近一次 ① 遍并把辨析表置顶在卡下（Anki 的 leech 思路，但不但「隐藏卡」——隐藏等于不背了）。

**词的排程**：沿用现表语义，索引换成词的接触次数：`interval(word.reps)`，前段 `0,0,0,1,1,2,2,3,3,4,5,5,5,5,5,7,7,7,7,7`，`graduated` 后 `14 → 30`。一期不换算法，但事件里存够 `err`/耗时/是否降级，供 P2 拟合。

### 5.2 句子：派生排程，不是记忆主体

```
sent.due  = min(word.due for word in sent.targetWords if word.stage != 'graduated')
sent.stay = 句内已无未毕业词 → 不再进任何队列（手点仍可跟读）
```
- 一次跟读该句 = 句内**每个**未毕业目标词各记 1 次接触（这正是「跟读一句 = 顺带背 3 个词」的正式记账，也解释了为什么句子必须只是容器）。
- 句子自己**不存** `reps/phase/nextDue`，只存 `lastReadAt`（用于「今天是否读过」与顺移账本）。

### 5.3 三池 + 时间预算装配

池子定义（都按词算，再汇成句）：

| 池 | 内容 | 优先级 | 单位耗时 |
|---|---|---|---|
| A 到期 | `word.due ≤ now` 且未毕业 | 最高 | 其所在句按复习计 `secReview` |
| C 新词 | `fresh`，按章节顺序 | 其次 | `secNew` |
| B 加深 | 未到期但处于 `seen/recognized` | 兜底（富余时间才装） | `secReview` |

装配算法（每天重算，不写「欠」字段）：

```
budget   = todayMinutes × 60
secNew   = pace.new / rate ; secReview = pace.review / rate ; secQuiz = 6 / rate
1) 装 A：按 due 最旧优先取词 → 汇成去重句集合 → 扣 Σ secReview
2) 若剩余 ≥ 0.6×budget：装 C（新句，按章节序）扣 secNew
3) 剩余装 B；装不满一句就整句不装（不截断句子）
4) 题量：② = n（队列每句 1 题）+ k（二次确认题，见 §6「两个语境」）；③ = n
   扣 (2n + k) × secQuiz；不够时**先砍 ③、再砍 k、最后砍 ②**（② 是晋升的唯一入口，尽量保住）
5) A 溢出：今天不排、明天现算重排（不写 debt、不显示「已欠 N 句」）
6) 地板保底：只要存在任何未毕业词，至少排够「地板」所需的量（判据见 §9.1）
```

- **混合句按 `secNew` 计**：一句里只要含未毕业以外的新词，就按新句耗时预算（宁可高估时间，也不要排出一个做不完的今天）。

- `pace` 已有实测能力：`samplePace()`（index.html:3977）用相邻两次跟读间隔、折算回 1× 基准、指数平滑，落盘 `prog.pace.{new,review,samples}` —— **这块保留不动，是现状里少数做对的东西**。
- 冷启动：`samples < 20` 时用常量兜底 `secNew=25`、`secReview=8`（现值），之后按 `w = samples/(samples+20)` 与常量混合。
- 面板顶部一句话交代结果，不交代过程：「今天 15 分钟：6 句 · 12 题（复习 4 句 · 新句 2 句）」。

### 5.4 日界与「今天」
- 所有 `today()/startOfToday()` 收敛到一个 `dayKey(ts)`；默认凌晨 **4 点** 日界，可在计划里选 0/2/3/4/5/6。
- 跨日界不重算、不清空已完成（`dayKey(lastReadAt) === dayKey(now)` 判「今天读过」）。
- streak 的「昨天」判定同样走 `dayKey`，凌晨 2 点读完不应算断更。

### 5.5 一句遮几个词
每句每次只遮 **1 个**词，选词顺序：`leech` > 池 A 里最旧到期 > 池 C 里未晋升。同一句在同一天不重复出同一词的题。

## 6. 每日三遍（任务模式流程）

三遍是**成块**的，不是一句一题交替 —— 这正是 P2「不打断跟读」的实现方式。

| 遍 | 做什么 | 遮什么 | 记账 | 时长感 |
|---|---|---|---|---|
| ① 通读 | 本次队列全部句子按现播放链完整跟读一遍（倍速、A-B 循环、逐句重听全部照旧可用） | 不遮 | 每个未毕业目标词 +1 接触；句子 `lastReadAt`；今日进度条走这一遍 | `Σ secNew/secReview` |
| ② 挖空填词 | 同一批句子，每句遮 1 个目标词，四选一（或回忆题降级）；**末尾追加「二次确认题」** | 遮**英文目标词**（保留词长的 `___`） | 答对 → 该语境计数 +1；两个语境都到过 → `seen→recognized`；答错 → 弹辨析表 + `due` 拉回今天 | `(n+k) × secQuiz` |
| ③ 看英文选中文 | 句子英文照显，高亮该词，选它在**这一句里**的中文义项 | 遮**中文义项**（选项取同辨析组兄弟词的义项） | 答对 → `recognized→owned` | `n × secQuiz` |

- **「两个语境」怎么考到**：一个词的语境有两个 —— 它所在的**课文句**，和它词卡上的**例句 `ex`**。课文句已经在 ② 里出了；例句题（`k`）在 ② 遍末尾以「卡面小卡」形式出：显示例句、遮词、四选一，不占句子位置。没有 `ex` 或 `ex` 里不含词头的卡（附录 A 那 18 张）暂时允许单语境晋升并记 `ctxMissing`，等修词后自动补严。

- 遍间小结（只有 3 个数字，且都只在这里出现一次）：读了 N 句 · M 个词晋升 · K 处填错。
- 每遍可独立跳过/单独执行（面板上「只做 ②」），但 ① 未完成时 ②③ 的题只从**已毕业以外**的词里出。
- 键盘/无障碍：② ③ 用 1–4 数字键，VoiceOver 下每个选项是独立 button 且带「选项 2 of 4，fog」朗读。
- ② 未解锁（该词没有裁决过的辨析组）→ 走回忆题（§7.4），不硬出四选一。

## 7. 出题引擎（② / ③ 的生成规则）

### 7.1 合法空格
只有 `[[key:display]]` 标记里的词能当空格：`key` 是词卡词头（小写、多词用空格），`display` 是句中实际词形（含大写/屈折，现有 183 处 key≠display）。遮的是 `display`，判分对的是 `key`。

### 7.2 选项来源（按优先级，成员一律是目标词 —— P10）
1. 该词所在**裁决过的辨析组**的其它成员；
2. 不足 3 个 → 补「义项团」里的其它**目标词**（§8.1 的 640 组机械团，成员本来就全都有卡；且必须过 §7.3 四层排歧）；
3. 仍不足 → 降级回忆题（§7.4）。

**被否掉的旧口径要记下来**：上一稿允许「干扰项可以是没卡的简单词（fog / haze / smoke）」，我还在汇报里把这当成好消息（说这样不用给简单词建卡）。按 P10 作废：**辨析与选项都只在目标词里取**。
带来的硬约束：`雾` 家族里目标词只有 `mist / smog / vapour / film`（`fog/haze/smoke/cloud` 没卡），所以这些词不能进这张辨析表，也不能当选项。

### 7.3 四层排歧（用来证明「这题不会多解」）
| 层 | 规则 | 数据 |
|---|---|---|
| L1 同义词黑名单 | 两词互相列进 `同义词：` 段（含反向、含现 1512 条无向边）→ **禁止**互为选项（空格填哪个都算对） | vocab `note` 段 |
| L2 中文义项重叠 | 候选与正确答案在**当前语境义项**上重叠 → 排除 | 卡 `m` 的分号分项 + 组内 `sense` |
| L3 词性/句法 | 空格语法位置要求的词性（由左右邻词粗判）与候选 `pos` 不符 → 排除 | 卡 `m` 首段 |
| L4 真实语料反查 | 把候选填回原句：若该句在 1833 句或三份 PDF 文本里能原样找到，或中文译文同样贴切 → 判多解，排除该候选 | `shadow/data/sections.json` + `work/ref/*.txt` |
| 出口 | 排完剩不到 2 个干净选项 → 整题降级为回忆题，并记 `degraded: true` | — |

### 7.4 降级回忆题
显示：中文译文 + 首字母 + 词长（`s _ _ _ _ _`）+（有词伙时）该词卡上一条词伙的首词。
判分：忽略大小写与首尾空格，允许编辑距离 ≤ 1（屈折/单复数容错）。答案文本本身不提示中文以外的信息。
> 这是 P3 与 P8 的交叉点：没有干净选项时，宁可不给选项。

### 7.5 「这题有问题」
每道题右上角一个小按钮 → 记 `flag` 事件（含句、词、选项集、原因枚举：多解 / 都不合适 / 辨析表说反了）。面板「我标的问题题」列表可一键重跑 L1–L4 并导出给 agent 复核。**标记过的问题题立即停用**（降级为回忆题），等他裁决。

### 7.6 答错之后
弹该组辨析表（复用现成渲染器 `renderCompareNote`，index.html:1522），正确项那一列高亮（现 CSS `.nb-tl` 已有强调底）；不自动播 TTS、不强制停留，读句子继续。

### 7.7 确定性
题目在装配队列时一次性生成为 `quiz[]` 并落盘；选项顺序用 `seed = hash(句号 + 词 key + dayKey)`，同一天重进任务模式不重排。这是可测试的前提（§14）。

### 8.2 辨析与出题的两套准入（同一批词，两条闸门）
| 数据 | 数量 | 写进辨析表？ | 能做互为选项？ |
|---|---|---|---|
| 段内同义项共现组（含同义对） | **220 组 / 443 词头** | 是（一期全做） | 部分 |
| 其中互为同义词的那 27 组 | 27 组 | **是**（最该讲清的一对） | **否**（填哪个都对，出题就是错题） |
| 全库义项团（同场但课文里没挨着） | 640 团 / 1116 词头 | 按需补（`看/瞥`、`走/奔` 家族） | 是（补第 2、3 个选项） |
| 卡上「同义词：」栏（PDF 同义替换资料） | 1512 条无向边 | 否 —— 它只服务卡上那一栏 | 否（L1 黑名单） |

一句话：**辨析是把近的词放一起讲清，出题是把近的词挡住只留一个对的**。所以辨析表可以含同义对，选项不行；两者的成员都必须是目标词。

### 8.3 一句话辨析的文体规格（本条是硬规定，门禁 2 按此判）

他的需求原话（2026-09-20）：「需要用非常精准的一句话辨析，来方便我非常非常快速地分辨它们的区别。」

`summary` 合格式：
```
damp = 摸上去潮（手感），moist = 微微潮（皮肤、土壤、蛋糕别太干）
mild = 冬天不冷（说天气），moderate = 不过火（说要求、价格、强度）
peer = 眯着眼费力看，glance = 快速扫一眼，glimpse = 偶然瞥见，peep = 偷看
```
四条硬性判据（不满足即退回重写，不算内容错）：
1. **每个成员一个钩子**：给场景、给搭配、或给一个限定词括号，读完能立刻判这一句该用哪个；
2. **≤40 字**，一行读完，不分行不分点；
3. **不复述中文义项**（`sense` 已写「潮湿」，summary 再说「都表示潮湿」= 零信息）；
4. **不许对仗废话**（「damp 侧重状态而 moist 侧重氛围」这类读等于没读的句子判不合格）。
   > 注意与 P8 不冲突：summary 是我们自己写的解释，不属于「造词」；**成员词表与例句仍必须有出处**。

每条成员的 `core` ≤ 12 字；`scene` 是一个看得懂的具体场景（现有 `抬眼看表 / 从门缝后探头 / 眯着眼看远处` 是标准件）。

### 8.4 组规格
- 一组 = 一个语义场，2–6 个成员，**成员全部必须是目标词**（有卡 + 在课文里被标）；混进非目标词按机械校验错误退回整组。
- **辨析组**按「同一段 + 同一个中文义项」成组，段内 2–6 个词就是天然边界（不做全库传递闭包，那会链出 31 词的大团）。
- **选项池**另算：必须是极大团（两两都过 L1 同义词黑名单），由脚本现算，门禁 1 校验。同一批词、两份清单，别混用。
- 每个成员必填：`w`、`sense`（中文义项）、`core`、`pos`；可选 `scene` 或 `eg`。
- 组必须有 `diff`（≥2 个对比维度）与 `summary`（按 §8.3 规格）。
- 一组成员要能在**不换章**的前提下被见到：段级共现组天然满足。

### 8.5 显示位置与数据落点
- **辨析表钉在段落末尾，一段一张**，表头写「这一段几个词都和 X 有关」。理由：共现是段级的（43.8% 的段 vs 3.7% 的句），钉句下会要么不出现、要么同一段重复三张。
  现状渲染器是句下插入（`noteBar` 按 `group` 在单句内去重，index.html:1544-1563），需要改为段级聚合；现有 3 张卡的标题「这一句…」同步改口径。
- **一句话在前，表格在后**：默认只显示标题行 + `summary` 一行，点开才展开对比表（他要在 1 秒内拿到判据，不是读一张表）。
- 数据仍写在词卡 `note` 里（`{type:'compare', group, title, items[], diff[], summary}`）；同组成员共享同一份对象。因成员全是目标词，**表里每个词都可点开卡**（不再有「无卡成员」这个特例）。
- 显示位置由「组 → 段落」映射决定，映射从 `sections.json` 现算（组内任一成员出现在该段 → 该段末尾出这张表），不新增数据字段。

### 8.6 生产管线（复用已跑通的两道门禁）
```
confusable_groups 出机械候选（段级共现 + 义项桶，打 src 标签）
  → tools/make_review_packets.py 分片（把该组的课文原句 + 中文译文一起塞进审核包，这是实测有效的做法）
  → 裁决代理做「选择题」：给 2~6 个成员 + 它们的段落，判「能不能互换 / core 与 summary 对不对」，禁止自由提词
  → 门禁1 tools/validate_card_patch.py（成员在词域内、义项不与卡冲突、词数、出处、summary 四条判据的机械部分）
  → 门禁2 独立审核代理（语义是否成立）+ 一句话专判（读一遍能不能判对，判不对退回）
  → 他抽查 → tools/apply_card_patch.py 落地 → bump SHADOW_DATA_VER → validate_data.py + npm test
```
- 落地器已有的护栏继续有效：**默认拒绝**（无审核结论不写盘）、辨析卡 `note` 是结构化对象时**不许被当文本覆写**（本轮刚修的那颗雷）。
- **给现有句子加 `[[标记]]` 不触发 `SENT_SHIFTS`**（句数没变）；只有插新句才必须登账 + 跑 `tools/check_shift_ledger.py`。辨析内容应尽量靠「加标记」而不是「插句」实现。
- 工作清单已落盘：`work/compare_groups_worklist.json`（220 组，每组带成员、共享义项、出现的段落与句号、是否整组同义），可直接切片派代理。

### 8.7 一期范围与出题解锁
- **一期把 §8.1 的 220 组全部做完**（这就是「整篇文章里很多很多这样的地方」的闭环，落在 153 个段落上）：按章分 6 批（原型图 E），每批过一遍门禁。
- 再加约 60–100 组「同场但课文里没挨着」的义项团组（`看/瞥`、`走/奔`、`雾/霾` 这类家族），目的是给 ② 补足选项，而不是无限扩表。
- **出题供给是内容线的验收指标**：186 个选项团里 168 个是双词团，加上那 27 组同义对根本不能出选择题 —— 光靠组内成员凑不出四选一，必须从 640 个义项团里补第 2、3 个干净选项。所以 P1 的退出条件里要报一个实测数：「② 能出四选一的词头数 / 3245」，预期量级在团覆盖的 1116 词头经过 L1–L4 之后的子集。
- **出题资格 = 组已裁决入库**。② 四选一的题量随辨析内容增长，未覆盖的词走回忆题。这是刻意的：错选项比没选项危险得多。

## 9. 打卡与动力：三层，两栏

### 9.1 三层（互不合并）
| 层 | 判据 | 与 streak 的关系 |
|---|---|---|
| **地板** | ① ≥3 句；若当天有可出的题再加 ≥3 题（② 未解锁时只算接触，见 U4） | **算 streak**，但面板老实写「今天只是地板」 |
| **有效日（扎实日）** | ① ≥ 当日队列 50% 且 ②③ 至少各做过 3 题 | streak 的常态档；地板日是它的降级档 |
| **词汇推进** | 今日净晋升词数（`fresh→…→graduated`） | **不进 streak**，只进栏 2 |

- streak 只有一个口径：**达标（≥地板）的连续天数**，旁边标注其中地板日数 —— `12 天 · 含 3 个地板日`。
- 取消现状的二值判定（`allDone` 要么 100% 要么没有，index.html:4464）。
- 与 §5.3 第 6 步互为约束：装配保证今天排出的量 ≥ 地板，所以「今天的任务比地板还少」不可能出现。

**断更回归的话术**：不说「欠 320 句」，说「上次读到这里，今天先排 6 句（你选 15 分钟）」。没有任何字段叫 `debt`。

### 9.2 两栏永不合并（P6 的硬规定）
- 栏 1「今天」：完成度、时间、streak、地板/有效日。
- 栏 2「词汇」：五个状态各多少词、今日晋升、重点词。
- 禁止出现任何把两栏折成一个「总分/总进度」的设计（包括环形图套两个数）。理由：今天 90% 完成度可能是因为今天只排了 3 句，两件事不能相互证明。

## 11. 数据模型与迁移

### 11.1 新 schema（localStorage key `ielts.shadow.v2`，一次存根，内部结构如下）
```js
plan  = { todayMinutes:15, boundaryHour:4, startDate:'YYYY-MM-DD', endDate:null, pausedNew:false }
words = { "<key>": { stage:'seen', reps:4, err:1, due:<ts>, firstSeenAt:<ts>, lastContactAt:<ts>, leech:false, ctx:{ "<sentIdx>":n, "ex":n } } }
sents = { "<sentIdx>": { lastReadAt:<ts> } }                       // 只有接触时刻，没有曲线
quiz  = { "<dayKey>": { seed, items:[{s,w,kind:'mc'|'recall',opts:[],ok}] } }
events= [ {id:<hash>, ts, type:'contact'|'quiz'|'flag'|'dayplan'|'stage', payload} ]   // append-only，待上传
daily = { "<dayKey>": { sentDone:n, quizDone:n, correct:n, promote:n, floor:true|false, minutes:n } }
legacy= { streak, cycleCount, ... }                                 // 只读快照，迁移后不再写
```
- `ctx` 是 P3/②「两个语境」的实现：键是语境标识（课文句索引或 `"ex"`），值是该语境里答对次数。**语境用「句内词形」而不是纯句号**，句子顺移时按 §11.3 规则降级为 `ctxUnknown`（保守：只丢二次确认，不丢词状态）。
- 队列项类型（P7）：`{kind:'sent'|'word', ref, pool:'A'|'B'|'C'}`，一期只会产生 `'sent'`。

### 11.2 迁移映射（一次性，幂等，保留老 key 30 天不动）
| 老数据 | 新数据 | 折扣 |
|---|---|---|
| `prog.sentences[i].reps` | 该句每个目标词 `reps += floor(句reps × 0.5)` | **打 5 折**：句子读 5 遍 ≠ 每个词有效接触 5 次（虚增会让一批词直接毕业，见风险 R5） |
| `phase: learning/solid/mastered` | 取 `min(阶段映射, 有②③证据)` | 迁移期没有任何检索证据 → 最高只能给 `seen`，`recognized+` 一律重新考 |
| `plan.totalDays/dailyMinutes` | `todayMinutes`（由 `planCapacity` 反推一次），丢弃 `totalDays` | — |
| `cycleCount/cycleSeen` | 只读快照进 `legacy` | 「轮」这个概念在新 UI 里**消失**，历史页可看 |
| `streak` | 保留数值，`daily` 缺失的天补 `floor:true` | — |
| 书签/播放位置云同步（现有 `{marks,pos}`） | 不动 | — |

迁移函数必须是纯函数 `migrate(oldRaw) → v2`，单测覆盖：空、损坏 JSON、只有 plan、只有 prog、reps 超界、老 key 已存在 v2。

### 11.3 与 SENT_SHIFTS 的关系（重要）
- 词状态以 **词形 key** 为主键，天然不受句子顺移影响 —— 这是把记忆模型从句子搬到词上的一个额外红利。
- 句级 `lastReadAt` 与 `quiz.ctx` 的句号仍需按现有 `SENT_SHIFTS` 账本重映射；改 `sections.json` 句数照旧必须登账，`validate_data.py` 第 14 条与 `tools/check_shift_ledger.py` 双算法回放继续把关。

### 11.4 缓存与发布
数据有改（词卡 note 结构、辨析组）必须 bump `SHADOW_DATA_VER`（index.html:1316，现值 `82fd9a4b6a`），`validate_data.py` 第 0b 条会拦漏 bump。发布链是 EdgeOne Pages 监听 `main`，无数据门禁 —— 所以上线前必须本地跑完 §14。

## 附录 D · 术语
| 术语 | 定义 |
|---|---|
| 目标词 | 句子里 `[[key:display]]` 标记、且在 `shadow/data/vocab.json` 有卡的词 |
| 语义组 / 辨析组 | 一组中文义项相近、但互换会说错英语的词（`mist/smog/haze/fog`）；成员可含无卡简单词 |

| 语境 | 一个词的「课文句」与「卡上例句 `ex`」两处实例，② 晋升要两处各答对一次 |
| 接触 | 对一个未毕业目标词的一次有效跟读（含它所在句被完整读过） |
| 晋升 | 词状态机前进一步；唯一进「词汇账」的事件 |
| 地板 | 最低完成量（① 3 句；当天有可出的题再加 3 题），保 streak，不装作「今天很充实」 |
