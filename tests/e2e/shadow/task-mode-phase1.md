## 为什么单独写一份

## 主路径（手工 8 步）

1. 点顶栏「今日」→ 出现**制定计划**屏：只有一个输入「每天有多少分钟」。
   - 断言：屏上没有「总天数」「慢/正常/快」这两条旧输入。
2. 选 15 分钟 → 「今天大约 N 句 · M 题」→ 点「开始这个计划」。
3. 面板变「今天」视图：**两栏并列**（左：今天 x/y 句 + 连续 + 完成度 + 还剩；右：词汇：今天晋升 + 三档计数）。
   - 断言：两栏没有被合并成一个「总进度」环或一个总数。
   - 断言：底部一行「今天 15 分钟：还剩 N 句 · 覆盖 M 个词」+ 小字「X 个词到期 · Y 个新词进队列 · Z 题」。
4. 点「开始今天的任务」→ 进任务模式。
   - 断言（2026-09-22 晚他**第二次**改口，覆盖当天下午那条）：底部只有任务条这一张卡，
     卡内**文字双行靠左、按钮全部靠右、关闭在右上角**。
     原话：「文字双行展示位于任务条左侧（核心信息在上、辅助信息下）；所有按钮位于任务条右侧；
     关闭按钮位于任务条右上方（悬浮后显示 退出任务模式，点击后提示是否要退出）；
     样式和播放条一致 glass 风格。」
     所以播放那组（播放·暂停 / 单句循环次数 / A-B / 倍速 / 书签）住在**按钮那一排**里；
     「读到第 N 句 · 章节名」那格在排里没位置，**藏掉**（句序号任务条已经在说 ① 通读 0/N）。
     **没有**进度条、**没有**展开收起键、**没有**第二颗上一句/下一句。
   - 断言：按钮排从右往左是 **下一句 → 再来 → 上一句 → 播放**（量水平坐标，
     且这一排可见按钮的垂直中心差 < 6px —— 这就是"同一行"的可测定义）。全页「上一句」「下一句」各只有一颗。
   - 断言：关闭 `#tbExit` 在**按钮排的上方**且贴卡片右缘（`top` 小于该排最小 `top`、右缘差 < 12px），
     常驻可点（旧版退出只能 汉堡 → 今日 → 退出任务模式 三跳），
     **且悬浮提示写着「退出任务模式」**、`aria-label` 同名、**这颗没有文字**（不占宽度）。
   - 断言：点 `#tbExit` **不立刻退出** —— 条子换成 `data-state="exit"`，正文变成「要退出任务模式吗？」，
     按钮排换成「继续做 / 退出」两颗，正文那排操作让位；点「继续做」回到 `read` 且仍在任务模式里，
     点「退出」才真的退出。（他 2026-09-22：「点击后提示是否要退出」。仍然零惩罚：不生成欠账。）
   - 断言：倍速 `#rateCycle` 在任务模式里**可见可点**（旧版被 CSS 藏死 = 功能丢失，别再退回去）。
   - 断言（2026-09-22 深夜再改一次，他：「底部按钮上方那些文字一堆，都没耐心看」）：
     条上**只有三个数** —— 主行 `① 通读 0/24` + 一条进度条（不再用文字复述百分比），
     辅行左边 `还剩 ~N 分钟`（唯一一个能行动的数），辅行右端 `本次 M 分钟`（小表，跟左边拉开两端摆）。
     **「今天 15 分钟」和「全部过完约某年某月」从条上撤掉** —— 设置屏 / 计划页 / 今日面板三处都还在，
     底栏是第四个重复点（`#tbEta` 这个节点已经不存在，`estimate-days.spec.ts` 守的就是"条上不再有第四个数"）。
     播放行标题是「读到第 N 句 · 章节名」，**不重复**任务栏那个 `n/N`（数字唯一性）。
   - 断言（高亮）：任务模式里**没有第二套"当前句"标记** —— `.sent.task-current` 全页 0 个，
     同一时刻 `.sent.playing` 恰好 1 个。点「上一句」高亮必须跟着往回走，且再点「下一句」
     回到原来那句（不是跳到它后面 —— 这一条只有队列位置真的对齐才成立）。
     口径出处：他 2026-09-22「高亮跟常规模式一样就行，不需要额外加描边」+「只能跟着下一句走，上一句没反应」。
     （口径出处：原型 `:248-253` + 他 2026-09-21 的缺陷报告；旧版那句「他拍板播放条不藏」在 docs/ 里查无出处，已作废。）
5. 连点「下一句」读完这批 → 弹**遍间小结**卡：三个数字（句读完了 / 个词今天见过 / 个词往前走了一步）。
   - 断言：分母不涨。读到第 10 句时仍然是 `x/24`，不会变成 `x/31`。
   - 断言：小结里没有「欠 / 待补 / 积压 / 轮」。
6. 点「开始 ② 挖空选择」→ 卡片出现：句中目标词被挖成下划线、给中文译文并把**这个位置的意思**用
   `<u>` 划出来、给 **4 个英文候选**（有且仅有一个是答案）；按 1–4 也能选。
   - 断言：② 态**那一组播放控件整组消失**（原型 :283-284 底部就只有任务条），同一行只剩「回看句子 / 跳过这题」两颗 + 退出；
     做题卡因此抬到更接近屏幕中部（390×844：旧口径 top=459 → 新口径 top=526）。
   - 断言：做题卡里**没有**「回看句子」这颗 —— 它唯一的家在任务条上（`#tbAgain` 在 ② 文案换成「回看句子」）；
     卡头只有「② 挖空选择」，**不带** `n/N`（今日进度只由任务栏说一次，§10.1 数字唯一性表）。
   - 断言：屏幕上找不到答案词本体（`innerText` 不含它）。
   - 打字提交：对 → 「对了。」；错 → 「正确的那一个是 …」，词的状态**不倒退**，`due` 拉回今天。
   - 断言：故意答错后任务栏出现「错 1」，进度数字没有减少。
   - 断言（2026-09-24 走查 #1）：答题后**做题卡里没有推进按钮**（`.qz-go` 全页 0 颗）——
     「下一题 / 小结 / 跳过这题」唯一的家是任务条那颗 `#tbNext`（它也是键盘 → 的等价物）；
     末题它写「小结」，中途写「下一题」，未作答时写「跳过这题」。卡上「对了。/正确的那一个是 X」那行与辨析表照旧。
   - 断言（2026-09-24 走查 #2）：答错的那道**在本遍末尾再考一次，只考一次**：
     分母 N 由 `base` 涨到 `base+1`（补考挂在同一份 `quizList()` 后面，分子分母同一份账），
     补考再答错也不会再涨；该词的 quiz 事件恰好 2 条（没有第二条记账路径）；
     「错 N」不双记；遍间小结那一行写「补考 1 个，对 0 个」，任务条上不加这个数。
   - 断言（2026-09-22 他追加）：**补考那道不许和原题长一模一样** —— 同一句、同一个空、同样四个词，
     但**排法必须不同**（`salt:'retake'`；换种子恰好洗回原样就左旋一格，所以这是保证不是运气）。
     引擎侧另有「② 的 salt 只换排法」一条：逐个数 60 个 (句,词) 组合，任何一条排法相同或候选集变了都算红。
7. 走完 ② → 小结 → 任务栏「今天完成」。**没有第三步**：
   - 断言：`todayPlan().items` 里所有题都是 `pass:2`（`pass:3` 一个都不许有）；`TASK.setPass(3)` 也被折回 ②；
     界面上（任务条 / 做题卡 / 面板三个视图）查不到「③」「第三步」「选义」字样。
   - 断言：答对一道 ② 之后该词的 `ok3` 从 0 变正（毕业凭据已搬到 ②），且答错不倒退。
   - 断言：点错的选项标红、正确的标绿。
   - 断言：出不干净四个候选的句子**直接不弹题**（该句只走 ① 通读），也不降级成默写。
   - 干扰项三档供给（PRD §7.2）：该词的已裁决辨析组 → 同段其它目标词 → **整本同词性的词**。
     第三档是 2026-09-22 复核时补的：只有前两档时全书有 188 个词（5.8%）在它们出现过的
     每一句里都凑不满四个候选（拦下它们的几乎全是词性闸，那是对的 —— 选项词性不齐，
     不看词义、光靠语法就能排掉），而这些词一旦出不了题就永远拿不到毕业凭据。
     第三档照样受词性闸与双解闸管，顺序按 `hash32(词头|候选)` 定：同词同批、换词换批。
   - 全库不变式（`plan-engine.spec.ts`，跑一次全表约十秒）：把 3245 个词逐个问一遍
     「你出现过的句子里有没有至少一处出得了题」，**出不了题的词必须 ≤ 5 个**。
     这条是给工期数字把门的：`estimateDays` 的模拟默认排进来的题都出得出来，
     两边一旦不一致，界面那句「全部过约 2028 年 6 月」就是空头承诺，而在界面上看不出来。
     当前实测只剩 `million` / `billion`（全书 `num.` 的卡太少，凑不满四个同词性选项）。
8. 走完 ② → 任务栏 `今天完成`；面板「词汇」栏的晋升数 = 这两步攒出来的。

## 事件流与断网（手工 3 步）

1. 读 3 句 → `TASK.pendingEvents().length > 0`；刷新 → 事件一条不丢，词状态一致。
2. 联网（桩）→ `cloudPush()` 返回 `sent > 0`，再推一次 `sent === 0`（靠 `event_id` 去重）。
3. 把桩设成拒绝 → 本地照常推进、事件留在待发队列、屏幕下方挂一条常驻提示（**不是弹窗**）。

## 刷新时没做完（或还没开干）→ 那一行变续读条（不弹窗）

1. 有计划、今天读了几句但没做完 → 刷新。
   - 断言：底部那一行（本来就是任务栏的位置）显示「今天的任务还没做完」+「已读 N/M 句 · 还剩 X 句」，
     两颗按钮是「今天先不做」和「接着做」；**播放条仍在，没被续读条挤掉**。
   - 断言：不是弹窗 —— 弹窗每刷一次都要点掉一次，就成了新的打断源（他 2026-09-20 明确否掉的）。
2. **今天一句没读**（全新的一天 / 全新存档第一天）→ 同样提一条（2026-09-24 走查 #5）：
   条上写「今天 N 句」+ 绿的那颗写「开始」，辅行留空（不给第二个数）。点它就进任务模式 = 1 步开跑。
   - 断言：顶栏「今日」那颗绿点与它同源 —— 把今天这批读完，`#btnToday.has-task` 跟着灭；
     绿点读的是 `todayLeftN()`（新引擎账，与条上那个 `n/N` 一份），不再读 `prog.sentences`（走查 #4）。
   - 断言：这条与那条断更 toast（`gap > 2` 才弹）同屏只冒一条 —— 条子挂着时不弹 toast。
3. 点「接着做」/「开始」→ 进任务模式，续读条让位给正常任务态。
4. 点「今天先不做」→ 这一行收起来；当天不再提（按「今天」记），隔天照常。换浏览器会话也算当天。
   - 提不提只有一本账：今天还有没读完的句子 且 今天没按过「今天先不做」。
     2026-09-23 他拍的口径是**「每次都提（只要今天没完成）」** —— 原来那把「这一趟浏览器会话提过没有」的
     sessionStorage 锁（`:start` / `:resume` 两格）已删：它让同一标签页第二次刷新就安静下来，
     于是看起来"时好时坏"，他当成 bug 报了。
     断言：今天没做完时，同一趟连着刷新三次，三次都提；把今天这批读完再刷新，就不提了。

## 2026-09-22 晚「底栏第二版」新增（4 条锁）

规格：`docs/superpowers/specs/2026-09-22-任务模式底栏第二版.md`。

1. **当前句只有一套高亮，上一句与下一句对称**：`.sent.task-current` 必须 0 个；同一时刻 `.sent.playing` 恰好 1 个；
   往回再往前要回到原句（不是跳过一句）。
2. **点 ✕ 先问一句**：`data-state` 变 `exit`、仍在任务模式、`#tbStay`/`#tbQuit` 露脸、正文那排操作让位；
   「继续做」回 `read`，「退出」才真退。
3. **② 也报剩余时间，且这个数来自真实速度**：一题没答完时只写「还剩 N 题」，**不许**出现「还剩 ~」；
   答过一题之后才出现「这批还剩 ~…（按你刚才的速度）」。
4. **底栏与播放条同款玻璃**：`backdrop-filter` 非 `none`、`border-radius` 与播放条同值；辅助行带「本次 N…」。
   同一条里顺手钉住：刚进模式的前 20 秒**不显示**「本次」（`setSessionStartForTest` 把表拨到 5 分钟前才可测）。
