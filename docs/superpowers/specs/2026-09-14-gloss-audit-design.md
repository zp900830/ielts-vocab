# 影子跟读翻译/释义排查修正（子项目 A）设计文档

- 日期：2026-09-14
- 状态：设计已确认，待实现
- 关联：子项目 B（待学词汇解析展示位）排后，本期不做

## 1. 背景

用户发现句译按单词首义误翻搭配义。例：`will not swear at the heavy traffic` 被译成"也不会对拥堵交通发誓抱怨"——`swear at` 是固定搭配（咒骂），与"发誓"无关。

根因定位（已验证）：

1. 词条 `swear` 的 `m` 本来并列两义（`v. 发誓；咒骂`），数据没错；
2. 但行内 gloss（`glossParts`）只取**首义截 12 字**，行内永远只显示"发誓"，误导了当初写句译的人；
3. 句译也按首义翻。数据缺义 + 显示丢义，同一个病根。

## 2. 范围

- 全量 `sentZh` 句译（6 大章，按条全扫）；
- 全部 3219 词条的 `m` 字段；
- 不碰：`paraZh` 段译（仅浏览不主动改；如发现明显误译，记入 diff 报告由用户定夺）、例句/例句译文、音标、`ex` 字段。

真相源：`shadow/index.html` 内联数据（无脚本 tái 生成，随改随生效）。`data/vocab.json` 为上游词表，仅同步 `m`。

## 3. 硬规则

- **R1 词条义项**：以 Oxford Learner's / Collins 常用义为准，多义并列，2–3 义为限。
- **R2 行内截断**：`glossParts` 从"取首义截 12 字"改为"取前两义拼接后截 12 字"。超长仍截断，完整义项永远在单词弹窗里。
- **R3 句译搭配**：维护一份"搭配敏感词表"（swear at、claim、make、take、get 等），脚本抽出所有含敏感搭配的"英文句 + 现句译"，按搭配义逐条重翻。

## 4. 改动落点

1. `shadow/index.html`：内联 `VOCAB[*].m`（R1）、`sentZh`（R3）、`glossParts` 函数（R2）；
2. `data/vocab.json`：同步 `m`（R1）；
3. 新增 E2E 断言：swear 行内显示两义（并入 `inline-gloss` 或独立用例）。

## 5. 工作流

1. 脚本抽取：英文句 + 现句译对齐表；全部词条 `m` 表；敏感搭配命中表；
2. 按 R1–R3 批量改；
3. 输出 diff 报告（英文原句 / 原译 / 新译，词条类同），用户逐条校验后合入；
4. `node --check` + 全量 17 E2E 通过后提交。
