## 为什么单独写一份

这块是「打开到哪、点什么、看到什么数」的全局行为，散在四个 spec 文件里。
需要一条能照着手工复述的案例：改任何一处界面口径时，先照这份走一遍，再决定动哪个断言。

## 前置

1. `{E2E_BASE_URL}/index.html`，不登录（云端用例自己塞假的 `window.supabase`）。
2. 清 `ielts.shadow.v2`、`ielts-task-plan`、`ielts-task-progress` 才是真·首启；
   只清 v2 会触发老进度迁移（那是另一条用例）。
3. 静态服务器有启发式缓存：改完代码用 `index.html?v=N` 破缓存，并确认新代码已加载。

## 主路径（手工 8 步）

1. 点顶栏「今日」→ 出现**制定计划**屏：只有一个输入「每天有多少分钟」。
   - 断言：屏上没有「总天数」「慢/正常/快」这两条旧输入。
2. 选 15 分钟 → 「今天大约 N 句 · M 题」→ 点「开始这个计划」。
3. 面板变「今天」视图：**两栏并列**（左：今天 x/y 句 + 连续 + 完成度 + 还剩；右：词汇：今天晋升 + 三档计数）。
   - 断言：两栏没有被合并成一个「总进度」环或一个总数。
   - 断言：底部一行「今天 15 分钟：还剩 N 句 · 覆盖 M 个词」+ 小字「X 个词到期 · Y 个新词进队列 · Z 题」。
4. 点「开始 · 先通读这一批」→ 进任务模式。
   - 断言：播放条的**上一句 / 下一句 / 再来全部可见可点**（回归锁：老版本用 CSS 藏掉过）。
   - 断言：任务栏 `① 通读 0/24 · 今天 15 分钟`；播放条标题是「读到第 N 句 · 章节名」，
     **不重复**任务栏那个 `n/N`（数字唯一性）。
5. 连点「下一句」读完这批 → 弹**遍间小结**卡：三个数字（句读完了 / 个词今天见过 / 个词往前走了一步）。
   - 断言：分母不涨。读到第 10 句时仍然是 `x/24`，不会变成 `x/31`。
   - 断言：小结里没有「欠 / 待补 / 积压 / 轮」。
6. 点「开始 ② 挖空填词」→ 卡片出现：句子中英目标词被挖成下划线、给中文、提示首字母 + 词长（+ 词伙首词）。
   - 断言：屏幕上找不到答案词本体（`innerText` 不含它）。
   - 打字提交：对 → 「对了。」；错 → 「正确的那一个是 …」，词的状态**不倒退**，`due` 拉回今天。
   - 断言：故意答错后任务栏出现「错 1」，进度数字没有减少。
7. 走完 ② → 小结 → 「开始 ③ 看英文选中文」：句子英文照显、该词高亮，四个中文义项（1–4 数字键可选）。
   - 断言：点错的选项标红、正确的标绿。
   - 断言：出不干净四个选项的词**跳过**，不在 ③ 里改成默写。
8. 走完 ③ → 任务栏 `今天完成`；面板「词汇」栏的晋升数 = 这三遍攒出来的。

## 事件流与断网（手工 3 步）

1. 读 3 句 → `TASK.pendingEvents().length > 0`；刷新 → 事件一条不丢，词状态一致。
2. 联网（桩）→ `cloudPush()` 返回 `sent > 0`，再推一次 `sent === 0`（靠 `event_id` 去重）。
3. 把桩设成拒绝 → 本地照常推进、事件留在待发队列、屏幕下方挂一条常驻提示（**不是弹窗**）。
