## A. 文字语义 / 术语一致性

### A1 【高】同一个「位置」有 6 种排法

| 出处 | 现在写的 |
|---|---|
| `app/app.js:824`、`app/app.js:609-610` | `第 3 / 40 句`（斜杠两侧各一个空格）← **你 2026-10-07 在随身听抽屉点定的基准** |
| `app/index.html:6779` | `第 3/40 句`（无空格） |
| `app/index.html:6786 / 6798 / 8840` | `第 2/6 篇`（无空格） |
| `app/index.html:4931` | `第3章 5/40`（第二个数没有单位，读者不知道 40 是什么） |
| `app/index.html:9135`、`9097` | `今天第 3 句 · 还剩 7 句`（进度条 tooltip / aria 两套说法） |
| `app/index.html:9831` | `已读 3/40 句`（无空格） |

改动面：7 处字符串 + 1 条 Playwright 断言（② 号测试已经在量抽屉那处）。
建议：定死一个模板 `第 {n} / {N} {单位}`，单位必填。

### A2 【高】引导语说「每天读多久」，屏上的真名却是另外两个

引导文案（用户照着找却找不到的入口名）：`app/index.html:6833`、`6861`、`8864`、`8869`、`9339`、`9444`、`10063`、`app/app.js:268` 都写「**每天读多久**」。
屏上真名：设置面板标题「**每天有多少分钟**」(`app/index.html:9719`、`9867`)、「**每天分钟数**」(`app/index.html:10062`、`app/app.js:1288`)。

改动面：约 10 处文案，纯字符串，零逻辑风险。
建议：把引导语改成带引号的真名 ——「先去「我的」→「每天有多少分钟」」。

### A3 【高】单词本筛选器与行内标签是两套零重叠的词表

- 筛选器：`待掌握 / 学习中 / 已掌握`（`app/app.js:19 WB_FILTER_LABEL`）
- 行内标签：`未见面 / 已见面 / 文中可辨 / 义项直连 / 已毕业`（`app/app.js:20-21 WORD_STAGE_LABEL`）
- 另一套：`app/index.html:6927 STAGE_LABEL`（少了 `fresh`，见 A11）

用户在筛选器点「学习中」，列表里的行却标着「文中可辨」「义项直连」——不知道哪些算「学习中」。
改动面：1 个映射表 + 3 个筛选按钮文案。判据本身（`app/app.js:981-985` 的 stage 划分）不动。
建议：以五态名为唯一词表，筛选器改成「全部 / 未见面+已见面 / 文中可辨 / 义项直连 / 已毕业」这种**由真状态组合**出来的档位。

### A4 【高】同一枚「目标词 N」胶囊，一处是「本篇」、一处是「本句」

`app/index.html:2754`（任务模式头部，本篇目标词数，**有** `title="本篇目标词数"`）与

### A5 【高】「A-B 循环」在两个应用里有四种写法

## B. 样式 token 一致性

先给三个统计（都是 `app/index.html` 单文件实测）：

- `font-size` **28 档 / 321 条声明**，其中 10 档只用过 1–2 次；`12` vs `12.5`、`13` vs `13.5`、`11` vs `11.5` 三对小数档并存。
- `backdrop-filter: blur()` **13 档**（8/10/12/14/16/18/20/22/24/28/30/32px + 一处 `1.5px`），跨三个应用。
- `box-shadow` **57 种写法 / 102 条声明**。
- 硬编码色：**249 个 hex + 362 个 rgba**；`#33302b`（深色描边）写死 **30 次**，而它明明有 token。
- 缓动：`cubic-bezier(.22,.61,.36,1)` 手写 **28 次**、`(.32,.72,.35,1)` 5 次，另有 2 条只出现过 1 次的曲线；**没有任何一条缓动被 token 化**。
- `:hover` 103 处、`:active` **12 处**、`:focus-visible` 8 处。

### B1 【高】`.fav-badge` 绕过了它自己的 token

`app/index.html:47` 定义了 `--note-bg: #fdf1dc; --note-text: #8a5f0a`，注释还写明「沿用既有的 `.reader-head .fav-badge` 用色」；
`app/index.html:1872` 却仍是 `background: #fdf1dc; color: #8a5f0a;` 字面量。**同两个色，一个有 token 一个没有**，改 token 时徽章不会跟着变。
改动面：1 行。零风险。

### B2 【高】2.0 有一处内联的 `#b07a10`，正是 3.0 判定「3.33:1 不合格」的那个值

`index.html:1658`：`style="background:#fdf1dc;color:#b07a10"`。
`app/index.html:1872` 的注释写着「M6 a11y：`#b07a10` 只有 3.33:1」→ 3.0 已改成 `#8a5f0a`，2.0 那颗没改。
改动面：1 处内联样式。这是**已知的对比度回归**，不是审美问题。

### B3 【高】两处小字用 `--coral-deep`，而这个 token 已被证明过不了 AA

`app/index.html:672`、`678` 用 `color: var(--coral-deep, #c0492f)` —— token 一定存在，fallback 是死代码；
而 `--coral-deep` 实际是 `#c9564a`（`42`），`app/index.html:1757` 的 `.link-danger` 注释已经写明「`--coral-deep #c9564a` 压白只有 4.27:1，11.5px 正文要 4.5」并因此**故意**硬写 `#c0492f`。
也就是说：同一个「危险动作红」，一处按 AA 收深、两处还在用 4.27:1 的 token 刷 11–12px 小字。
改动面：2 处（把那两处换成同一个达标色，或给 token 分「大字/小字」两档）。

### B4 【高】深色档的描边/底色大面积写死

`body.dark … { border-color: rgba(255,255,255,.08) }` 实测 6 处、`#33302b` 30 处、`#252220` 若干（如 `app/index.html:2432`）。
深色相关声明一共 196 处成对写（**没有发现漏配深色导致亮斑**，这点是干净的），但值散落，改一次深色底要扫 30 处。
改动面：中（机械替换，但要逐个确认不是「故意不同」）。

### B5 【高】抽屉注释自称「配方同 `.audiobar`」，数值其实已经漂了一档

玻璃配方（`linear-gradient(145deg, …)` 三段白）实测：

| 元素 | 值 | 出处 | 注释怎么说 |
|---|---|---|---|
| `.audiobar` | `.65 → .25 → .15` | `app/index.html:431` | 基准 |
| `.task-bar` | `.65 → .25 → .15` | `1451` | 「与 `.audiobar` 同一套」✅ 名副其实 |
| `#lcDrawer` | `.72 → .34 → .24` | `2450` | 「配方同 `.audiobar`」❌ 整体偏亮偏实 |

也就是**注释在撒谎的一处只有抽屉**：它比基准白 7–9 个点，所以在本页所有玻璃件里看起来更「厚」。
改动面：1 条渐变（3 个数值）。要么把抽屉拉回基准，要么承认它更不透明并改掉注释 —— 但两者不能继续互相矛盾。

## C. 排版 / 触区（移动端可用性）

### C1 【高】手机上最高频的播放键，有效触区只有 30px

- `app/index.html:194`（`@media (max-width:700px)`）给 `.audiobar .btn, .tb-btn, .ps-opt, #btnMenu, #edgeTab, aside .x` 统一 `min-height:44px`；
- 但同一个 media 块里靠后的 `app/index.html:1171-1173` 又把 `.audiobar .btn` 压回 `min-height:30px`，**并且 `.audiobar .btn::after { display:none }` 把外扩热区一起关了**。
- 结果：这条 44 清扫对播放条**完全无效**。`shadow/index.html:1059` 有 44×44 的补丁，3.0 这边缺。

改动面：删 1 条 `display:none` + 调 1 个 `min-height`。风险：播放条会变高一点点（触区靠 `::after` 外扩则视觉零变化）。

### C2 【高】滚动后头部收缩档，触区掉到 40 以下

`app/index.html:1823`（`.reader-head.shrunk .tr-help` 20×20，外扩 `-10px`）、`1824`（`.nav-arrow` 高 22，外扩 `-9px 0`）。
而且 `playwright-tests/journeys/app3/a11y.spec.ts:275` 那条触区断言**不滚动**，所以这条一直是假绿。
改动面：2 条外扩值 + 1 处测试补滚动。

### C3 【高】手机端唯一的顶栏入口 `#btnMenu` 被压成 24×24

`app/index.html:1046` `body.nav-menu #btnMenu { min-width:24px; min-height:24px }` —— id + class 的特异性压过 `194` 的清扫。
改动面：1 条规则（补 `::after` 外扩比放大视觉盒更稳）。

### C4 【高】390 屏上「一屏水平缘」有 5 档

## D. 交互一致性

浮层开合目前**三套实现并存**：inline `style.display`（`openModal`/`closeModal`）、`.open` class、`hidden` 属性。下面 3 条高优先级里 2 条就是这个混用直接造成的真 bug。

### D1 【高】词库抽屉的锁滚会永久残留（同一个 class 挂在两个不同的宿主上）

`togglePanel`（`app/index.html:5682-5692`）：移动端把 `panel-open` 挂在 **`.layout`** 上并写 `document.body.style.overflow='hidden'`（`5687-5688`），桌面端把**同名 class** 挂在 **`body`** 上（`5690`）。
CSS 也分成两套认这两个宿主（`817` `body.panel-open aside` vs `1147` `.layout.panel-open aside`）。
于是：手机开着抽屉 → 转横屏 / 把窗口拖宽过 700px → `panel-open` 还在 `.layout` 上，桌面那套不认它；而唯一会调 `togglePanel()` 去清锁滚的遮罩处理（`5600`）要求 `matchMedia('(max-width:700px)')` 仍成立，此时已经不成立 → **`body.style.overflow='hidden'` 再没有任何路径清掉，页面永久锁滚，只能刷新**。
改动面：1 个函数（锁滚收进一个「无条件清」的出口 + class 只挂一个宿主）。

### D2 【高】☁ 云同步浮层有两套显隐机制，状态会分叉

`#cloudWrap` 一边由 `.open` class 控制（`app/index.html:4160` 外点关闭、`5520` ESC 关闭），一边由 inline `display` 控制（`openModal`/`closeModal`，`4156`、`4663`）；
而 `closeAllOverlays` 的清单 `OVERLAY_WRAP_IDS`（`5541`）只列了 5 个 wrap、只摘 `.open`，`5590` 那段读状态的代码于是可能拿到自相矛盾的结论。
改动面：统一成一套。`markWrap / abWrap / loopWrap / rateWrap` 走的是同一份代码路径，一起收。

### D3 【高】焦点陷阱已有实现，但三个浮层没接

`app/index.html:5502 _trapFocus()` 写好了，只在 `openModal`（`5526`）里挂。
`#todayPanel`(`2938`)、`#lcDrawer`、`#startPickPop` 都标了 `role="dialog" aria-modal="true"`，但 Tab 能直接跑到背后的页面上 —— `aria-modal` 在这里是句空话。
改动面：3 处调用，低风险。
