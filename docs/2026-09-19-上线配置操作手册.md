## 第 1 步：填 Supabase 的两个环境变量

**去哪：** 腾讯云 EdgeOne 控制台 → 你的项目列表 → 点开 `ielts-vocab` → **项目设置** → **环境管理**。
里面固定有两行：**生产**（对应 main 分支）和 **预览**（其它分支）。点「生产」这一行的 **编辑** → 找到 **环境变量**。

**加两条：**

| 变量名 | 变量值 | 去哪拿值 |
|---|---|---|
| `SUPABASE_URL` | `https://nhqevdkjqzgnyjbijwso.supabase.co` | Supabase 控制台 → 项目 → Project Settings → API → Project URL |
| `SUPABASE_KEY` | Project **anon** public key 那一整串 | 同一页，**publishable/anon key**，不要复制 service_role key |

要点：
- 单个变量值上限 **500 字节**。anon key 约 300 字符，一条放得下；**别**把 URL 和 key 拼在一起。
- 生效范围文档里自相矛盾（一处写「按环境」，一处写「作用于整个项目」）。看到下拉框就两个环境都填，省事。
- **改环境变量不会自动重新部署**，只作用于"下一次部署"。所以填完必须做第 2 步。
- 如果你不想把 key 粘进控制台：更干净的做法是改用 GitHub Actions 构建（EdgeOne 官方支持），把它当 Actions secret。本轮不做，留给你选。

**确认：** 环境变量列表里两条都在，值显示为掩码。

## 第 2 步：让构建跑起来（框架预设 / 输出目录 / 构建命令）

我已经在仓库根放了 `edgeone.json`：

```json
{ "buildCommand": "node scripts/build_site.mjs",
  "installCommand": "true",
  "outputDirectory": "dist" }
```

**去哪核对：** 项目设置 → **构建部署配置**，确认四项是：

| 字段 | 应为 |
|---|---|
| 框架预设 | 其它 / 静态（不要选 Next.js 之类） |
| 根目录 | `./` |
| 构建命令 | `node scripts/build_site.mjs` |
| 安装命令 | `true`（仓库根没有 package.json，必须显式设，否则平台可能自己去 npm install） |
| 输出目录 | `dist` |

如果控制台里这几项**显示的还是旧值**，说明 `edgeone.json` 没能覆盖控制台设置 —— 就在界面上手动改成上表的值并保存。
（**安装命令这一步别省**：如果安装命令跑了 `npm install` 而输出目录又是 `/`，`node_modules` 会整包变成公网文件，还会撑爆 2 万文件/5 GiB 限制。）

**触发一次部署：** 项目列表 → 右侧「⋯」或详情 → **重新部署**。或者直接推一个提交（main 分支会自动部署）。

**确认（三条都要过）：**

```bash
curl -s -o /dev/null -w "config %{http_code}\n" "https://ielts-vocab.bond/shadow/config.js?cb=$(date +%s)"
curl -s -o /dev/null -w "docs   %{http_code}\n" "https://ielts-vocab.bond/docs/"
curl -s "https://ielts-vocab.bond/shadow/index.html?cb=$(date +%s)" | grep -o 'SHADOW_DATA_VER = "[a-f0-9]*"'
```

期望：`config 200`、`docs 404`、版本戳是当时最新的那个（本轮为 `63ab652f35`）。

再在浏览器里开跟读站 → 登录一次 → 播一句 → 回 Supabase 控制台 → Table Editor → `user_data`，应能看到你自己那一行，`marks`/`pos` 有内容。**这一步才算云同步真的通了。**

**如果部署红了：** 进部署详情看构建日志（新版把每一步分开显示）。两种最可能：
- 找不到 `node` 或版本太老 → 项目设置里有个 **Node.js 版本** 下拉，选 20/22/24 任一。
- 构建脚本自己报错 → 日志会写「白名单漏了页面引用的文件：xxx」，把那一行发我，我补白名单。
- 部署失败时**站点仍停留在上一个版本**，不会白屏。

> 顺带一提：`netlify.toml` 和 `_redirects` 这两个文件 EdgeOne 完全不认（官方迁移文档要求改写进 `edgeone.json`），它们是死的；我不删是怕你以为我动了别的东西，你想清就清。

## 第 3 步：开 RLS（4 张表）

**去哪：** Supabase 控制台 → 项目 → 左侧 **SQL EDITOR** → New query → 把仓库里这段**整份**粘进去 → Run：

```
sql/2026-09-19-user-data-rls.sql
```

这段是幂等的（可反复执行），做四件事：
1. 建 `user_data` 表（`user_id` 主键 + `marks` + `pos` + `updated_at`）—— **这张表目前没有任何地方建它**，而跟读站每天在往里写；
2. 开 RLS，并给「只能读写自己那一行」三条策略；
3. 末尾两条 SELECT 打印四张表现状 —— 你直接把结果截图发我；
4. 一段**注释掉**的可选项：`learning_data` 的现有策略额外要求「profiles 里有我且 role 正常」，一旦注册触发器丢失，用户连自己的学习数据都读不到且前端静默失败。单人使用下这个条件没有安全收益。**默认为不动**，要放宽再取消注释执行。

**确认：** 结果里四张表 `已开rls = true`；策略数为 `user_data` 3、`profiles` ≥1、`learning_data` 1、`app_settings` **0**（这张有意零策略，只有 service_role 能通过 Edge Function 访问）。

顺手在 Supabase 里再确认一件事（我没权限看）：**Authentication → Policies/URL Configuration** 里有没有把 `ielts-vocab.bond` 列进 Redirect URLs。没加的话，邮箱登录链接会跳错地方。

> 本地跑测试前留意：`playwright-tests` 会自己起两个静态服务，端口 **8931**（shadow）和 **8932**（仓库根，给主站/admin 用）。
> 这两个端口被别的进程占着时它会直接复用 —— 我这次就被自己起的 8932 服务坑过一轮，主站 4 个测试假红。
> 复跑前先 `lsof -nP -iTCP:8931 -iTCP:8932 -sTCP:LISTEN` 看一眼。
