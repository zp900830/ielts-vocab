他原话（逐字，两次附截图）：

> 我不太明白，所有辨析卡上漏出一个「该段原文」是何意，这就是你重构后的结果？

两处**根因不同**，一件是数据层面的历史坑（**不是**重构引入），一件是当天渲染层清洗的真实回归。分开说。

## 一、「该段原文」：3 张卡的 summary 是历史坏数据（非重构引入）

### 事实

`data/vocab.json` 里 `cmp.summary` 有 3 张卡写着占位文本：

| 卡 | summary（修复前） | title（一直是好的） |
|---|---|---|
| belt | `辨析：该段原文简单记：该段原文` | belt 是「腰带；（机器）传送带」；strap 泛指「带子；皮带条」。 |
| dwelling | `辨析：该段原文简单记：该段原文` | reside 是动词「居住」（正式）；dwelling 是名词「住宅；住所」。 |
| exterior | `辨析：exterior 说哪一面，outward 说往哪跑，都没说“外表”。简单记：该段原文` | exterior 是「外面；外部的」（n./adj.）；outward 是副词「向外」… |

卡片折叠行 = `compareLine()` 取 summary 里「简单记：」后面那半句 → 显示成「该段原文」。

**不是本轮重构引入的**：`git show 693a706^:data/vocab.json`（数据层清洗**之前**）里这三张卡
就是 `辨析：该段原文（章2 段15） 简单记：该段原文（章2 段15）` —— 清洗只是把「（章N 段M）」坐标剥了，
留下「该段原文」四个字。全库计数：清洗前后都是 **3 张卡 / 5 次出现**。

**真正的来源**：落地器在写这三张卡时把草稿里那张表的标题「**该段原文（章N 段M）**」错位当成了
summary 的两个槽位内容（「辨析：X 简单记：Y」两处都取了它）。

### 修法（改数据）

按卡内素材补写正确文案（结构对齐其它 217 张的正常形态「辨析：…。简单记：…」；
「简单记」半句宽度按门禁口径 ≤40 分别实测 33 / 19 / 21.5）：

| 卡 | 修复后 summary |
|---|---|
| belt | 辨析：belt 要打洞、束在身上或机器上；strap 挂在包上、绕在手腕上。简单记：belt = 束的（belt needs holes），strap = 挂的（strap hangs loose） |
| dwelling | 辨析：reside 是动词「居住」（正式），dwelling 是名词「住宅；住所」。简单记：reside = 住的动作，dwelling = 住的地方 |
| exterior | 辨析：exterior 说哪一面，outward 说往哪跑，都没说“外表”。简单记：exterior = 外头那一面，outward = 朝外的方向 |

（belt/dwelling 两条「辨析」句是按卡内 items/diff 素材新写的；exterior 的前半句原样保留。
他若要改口径，改这一行即可。）

连带：`SHADOW_DATA_VER` `2eebbac4cc` → **`58df06e811`**（脚本重算）。
防回归：`cmp-caret.spec.ts` 数据层锁新增 probe `维护语·出处占位 /该段原文/`。

## 二、「空白单元格」：渲染层「整段删除」规则误删正文（**是**当天回归）

### 事实

`index.html` 的辨析卡显示清洗（`cmpCleanText`，2026-10-12 提交 `3ed4a83` 引入）里有**两层**：

1. **括号层**（`cmpCleanBracket`）：剥「（879）」「（卡上例句）」「（课文 474 走 n.）」「（课文译文）」
   这类括注 —— 目标正确，保留。
2. **整段删除层**：按句读切分后，**段以维护词开头就整段删掉** —— 出问题的一层。

`CMP_NOTE_HEAD = /^\s*(卡|词伙|课文|本书|…)/` 把「**课文**」写进了维护词表，而「课文」是卡片正文的
**常用内容词**。全库回放（复刻同款正则跑 220 张卡）：

| 指标 | 数值 |
|---|---|
| 被整段删除的段 | **466** |
| 其中以「课文」开头 | **463**（其余 3 条以「卡片上」开头） |
| 逐条判定为**真维护注**的 | **0** |
| `dim`（维度标题行）被清空 | 306（89 张卡受影响） |
| `both`（两词合说格）清空 / 截断 | 50 / 197 |
| `core` / `scene` 被清空 | 2 / 1 |

被删的原句长这样（**全是正文**）：
- 「课文里它挂在什么上」（维度标题 → 渲染成**空白行**，即他截图圈的「占一行面积什么也没有」）
- 「课文里"长条"有 6 张卡片（…）；belt、strap 是成品上的一部分」（both 前半句被删）
- 「课文译文自己把 damp 处理成「潮」、把 humid 处理成「闷热」」（整句被删）
- 「课文里唯一那辆大的」（item.core 被清空 → 成员表空格）

真维护注都在**括号**里，括号层已经处理了 —— 这一层从来不需要。

### 修法

**移除整段删除层**（`CMP_NOTE_HEAD` 与 `segs/filter` 两段代码），只留括号层。
`dim` 等字段不必单独豁免 —— 误删的唯一来源就是这层。

修后全库回放：`dim` 变动 **0**、`core/scene` 空 **0**、`title` 变动 0；
`both` 仍有 123 处变动，**全部是括号注剥离**（「（课文译文）」「（课文，零冠词）」），符合预期。

### 锁

- 新用例 `cmp-caret.spec.ts`「辨析卡正文清洗不许误删」：桩数据同时放**该留的**（`dim`＝「课文里它挂在什么上」、
  both 正文句、core 正文句）与**该剥的**（「（课文译文）」），断言维度标题行**逐条非空**、both/core 正文完整、
  括号注仍剥。
- 反向验证：把整段删除层临时加回 → 新用例立刻红（维度标题变空串），与本机报障现象一致。
- 既有锁「辨析卡显示清洗」的靶子同步修正：`课文` 从「绝不出现」名单里去掉（它是内容词），
  保留「卡上 / 词伙 / 本书」；括号注仍不许上卡面。

## 教训

1. **「维护词表」里不许出现内容词**。这批规则的靶子应该是**注的形态**（括号、坐标、出处），
   不是**词**。「课文」被当成维护词，一次删掉 466 段正文，89 张卡受害。
2. **删除型清洗必须带「误删回放」**：`3ed4a83` 当时的验证只查了「括号数字残留 = 0」，
   没查「删掉的东西是不是正文」——所以 306 个维度标题变空白行没被拦住。
   现在的验证口径：修完跑「全库回放」，逐字段看变动量，并对被删/被改样本**人工过一遍**。
3. **数据层的坏数据要能追溯到来源形态**：这 3 张卡的 summary 从落地起就是错的，
   历轮清洗都没识别（因为「该段原文」不在任何维护词表里）。修完已把该词立闸。
