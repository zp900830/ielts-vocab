## 1. 核心诊断：先看清症状之源

这四条是根因。下面 90% 的条目都是它们的投影；只做下游条目会持续返工。

### 诊断 A：项目缺少反馈回路，所以只能靠"排查报告"代替数据

`docs/PRD.md:1143-1153` 定义了 7 项成功指标（周活 ≥50、日均学习 ≥15 分钟、完读率 ≥40%、测验正确率 ≥65%、P95 加载 <3s、云端 TTS 成功率 ≥95%、7 日留存 ≥30%）。**其中 6 项没有任何采集手段**，唯一存在的度量是 admin 看板的注册数 / 7·30 日活跃 / 有数据用户数 / 测验正确率。

后果可以直接观测：12 天 337 个提交、约 2.1 万行排查文档，但没有任何一条能回答"这 14 轮优化让学生多学会词了吗"。09-18 上线的整套 SRS 计划引擎，无法判断它是否提高了留存。

### 诊断 B：同一份 3219 词被劈成两套互不兼容的表示 + 两套进度账本

| | 主站 `index.html` | 跟读站 `shadow/index.html` |
|---|---|---|
| 词典 | `data/book.json`（数组行，无 note/辨析） | `shadow/data/vocab.json`（含 `ex/exZh/uk/us/note`） |
| 进度键 | `yasiVocabV1` / `learning_data` | `ielts-*` / `user_data` |
| SRS 粒度 | 词级（且只服务收藏词） | 篇/句级 |
| 播放器 | 有 scrub、倍速、音色选择 | 有 AB 循环、单句循环、书签 |
| 访问模型 | 游客锁 14/15 篇，需登录+审批 | 全开放 |
| 互相链接 | **0 处**（主站搜不到 shadow，shadow 搜不到主站） | 同 |

两边各有一半功能，谁也不知道对方存在。这是"重复路径 / 口径不一致 / 修一处漏一处"的总根因。

### 诊断 C：内容资产是真的，但教学法接线没接

3625 个目标词 × 135 篇故事 × 1809 句跟读，paraZh/sentZh 与段落数组长度全对齐（0 错位），正文 3219 个标记键精确命中词典（0 悬挂）。这是最贵、最难复制的部分。

但词的**复现分布**不合格（实测见 §4），且复习队列默认不服务目标词。所以"有好内容"和"能背单词"之间缺的那段线，就是 §4 整章。

### 诊断 D：门禁与绿灯校验的不是线上跑的东西

- AGENTS.md 要求 `validate_data.py` 必须 PASSED —— 它校验 `shadow/data/*` + `data/vocab.json`，**恰好都不是主站运行时加载的文件**（主站只要 book/sup/stories/covers，`index.html:1148-1149`）。
- 它当前输出 `Validation PASSED`，但只做 4 项检查，且 `scripts/validate_data.py:30,42-44` 全部 `.lower()` 比较，而 `shadow/index.html:3290` 也 `.toLowerCase()` —— **检测器和被检测代码互相打掩护**，16 个大小写脏键永久隐身。
- 它不查本次反复返工的全部数据类缺陷：`；；`（实测 0 命中该检查）、义项数、模板句错位、中文里混外文。
- **CI 根本不存在**（`.github/workflows` 目录都没有）。所有门禁全靠人自觉。

## 16. 需要你先拍板的一件事（不定则上面持续返工）

**两个应用的关系。** 现在主站有 scrub/倍速/音色/测验/统计，跟读站有 AB/循环/书签/SRS，**各有一半**；主站游客锁 14/15 篇且要审批，跟读站全开放；两站零交叉链接。

三条路：

1. **合**：一个带「阅读 / 跟读」两模式的壳，共享一套进度 store 和一个词典真源。工作量最大（估 5–7 天），但 §3/§4/§6/§8 的大部分条目会自然消失。
2. **分**：明确主站只做阅读·测验·词级复习，跟读站只做跟读；两站互相开门，词级/篇级账本通过同一账号契约只读互认。工作量中等（估 2–3 天）。
3. **弃一**：承认精力只够维护一个，把另一个降级为只读。

我的判断：**选 2**。理由是 §12 的复发台账显示，当前瓶颈不是缺功能而是缺收敛；合并会把两套历史包袱焊死在一起，而"分但互认"能在不动播放引擎的前提下先止住"练了两遍不知道练过"。

这个决策不定，上面所有条目都会持续返工 —— 因为同一个功能要在两处各修一遍。
