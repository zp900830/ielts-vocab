## 2. blocker：两套「当前句」标记必然不同步

描边那套（`.sent.task-current`）只由 `goToNextTask()` 移动，而「上一句」这颗按钮直接调全局 `step(-1)` —— 它不认识这个类。后果不止是"看着不动"：

1. 屏幕上同时有两句被标成当前（描边停在旧句、常规底纹跟到新句）；
2. 队列位置 `taskPos` 也停在旧句，于是**再按「下一句」，记的是那句并没在读的句子的进度**。

所以修法不是"给 `step(-1)` 补一行同步"，而是**取消第二套标记**：「我在哪一句」全站只有 `.sent.playing` 一个真值（它本来就跟着 `playFrom` → `paint` 走，上一句/下一句/键盘/自动链全都经过它）。`taskPos` 则改由新的 `TASK.prev()` 在翻句后对齐到屏幕上这一句。

## 3. 底栏结构

```
#taskBar（玻璃卡，浮在底部：左右 24px 收边、22px 圆角、bottom 12px + 安全区）
├── .tb-close#tbExit          绝对定位右上角，只有图标，title=「退出任务模式」
└── .tb-body（宽屏一行：文字左 / 按钮右；≤700px 折成两行：文字在上 / 按钮在下）
    ├── .tb-text
    │   ├── .tb-title#tbTitle  核心行：① 通读 64/141 · 今天 15 分钟
    │   └── .tb-line2          辅助行：这批还剩 ~32分5秒 · 本次 8分钟 〔全部过完约 2027 年 9 月〕
    └── .tb-btns               播放组 → 上一句 → 再来 → 下一句（从右往左重要度递减）
```

状态机沿用「一条栏多种态，只换内容不藏控件」：`idle | read | quiz | done | resume | **exit**`。新增的 `exit` 态不弹层、不新开弹窗——正文换成问句，按钮排换成「继续做 / 退出」。

## 4. 两个数怎么算（不许编）

- **本次已用多久**：`sessionStart`（进任务模式那刻）到现在，每 15 秒自己走一次表。**前 20 秒不显示** —— 刚点进来就写「本次 0秒」看着像坏了。
- **② 还剩几分钟**：`quizStart` + 已答题数算出**他自己刚才的每题秒数**，再乘剩余题数。**一题没答完时只报「还剩 N 题」，不给分钟数** —— 一个凭空来的数比没有数更坏（这条是「数字不许编」口径的延续）。
- 顺手抓到：① 态那行「这批还剩」以前写成 `secNew() / rate`，而 `secNew()` 本身已经除过倍速 —— **倍速被除了两次**（1.5× 时把剩余时间少报一半）。改成 `secNew()` 一次。这是同一天在引擎里抓到的 `rate` 平方坑的第二个现场。

## 5. 明确没做的

- ② 态辅助行原来的提示语（「选出填回空格的那个词」/「答错不倒退，今天之内还会再见到它」）让位给剩余时间 —— 四选一没什么要教的，而「还要多久收工」正是这一步唯一想知道的数。答错的安慰话仍在做题卡里。
- 窄屏（≤560px）「再来 / 下一句」仍退成纯图标：按钮排自己一行也放不下带文字的九颗（实测过）。名字由 `title`/`aria-label` 说。
- 退出确认**不做**挽留：文案只报「今天的进度已经记下了，退出不会欠下什么」，零惩罚口径不变（竞品拆解里这是相对多邻国/Anki 的差异化资产）。

## 追加（同夜第三次改口）：条上只留三个数

他看着成品说：「底部按钮上方的那些文字一堆，都没耐心看。是否可以结构化的展示，信息有主次。」
数了一下，条上同时报 **5 件事**（读到哪 / 今天预算 / 还剩多久 / 本次多久 / 全书何时过完），全是同一种灰、同一号字。

给他三个选项（只留三个 / 全留但拉开层级 / 只留进度其余点开），他选**「只留三个」**。落成：

| 层 | 内容 | 样式 |
| --- | --- | --- |
| 主行 | `① 通读 9/45` + 一条 3px 进度条 | 13.5px / 700，进度条吃掉剩余宽度 |
| 辅行左 | `还剩 ~15分钟` | 11px / 中灰 —— **唯一一个能立刻行动的数** |
| 辅行右 | `本次 6分35秒` | 10.5px / 更浅，`margin-left:auto` 顶到右端 |

撤掉的两件：**「今天 15 分钟」**（预算，设置屏 / 计划页 / 今日面板都有）和**「全部过完约 2028 年 3 月」**
（`#tbEta` 整个节点删掉，`paintTaskEta` 一起删 —— 「四处同源」从此是**三处**）。
进度条替掉"已完成 x%"这类废话字：同一行左边本来就是 `n/N`，画出来比再说一遍短。

② 态进度条跟的是**做题进度**（`quizCursor / quizN`），① 态跟的是**句子进度** —— 主行标题各说各的计数器，
条就在它正下方，读法不歧义。续读条（`data-state="resume"`）也补了一次填条，否则会出现「已读 2/24 但条是空的」。

**措辞跟着收**：`这批还剩 ~` → `还剩 ~`（条上只剩一个时间数，不必再强调"这批"）。

## 附：探针改口径之后又抓到的四条（2026-09-22 深夜第二轮）

跑 `node work/task_mode_audit.mjs` 复量玻璃底对比度时发现：**上一轮那份报告本身在骗人**，
先把探针修对，才轮到产品。

### 先修探针（三条都是它自己的错）

1. **深色模式从来没被测过。** 探针找的是 `#themeBtn` / `[onclick*="dark"]`，
   真开关是 `#btnDark` + `onclick="toggleDark()"`（大写 D，选择器大小写敏感）→ 点了个空，
   报告里那半节「深色对比度」量的其实还是亮色。**假覆盖比假红更坏**：它让人以为查过了。
   现在改成点 `#btnDark` 并**断言 `body.dark` 真的挂上**，挂不上就报 P1「这一节没测到」。
2. **半透明玻璃把对比度量乐观了。** 旧写法一路向上找第一个不透明 `background-color`，
   等于把玻璃那几层 `.65/.25/.15` 当不存在。改成按由外向内把所有半透明层叠回底色，
   渐变再取最不亮那一档；判据也从「字号 != 11px」换成 WCAG 真正的分档（大号字 3:1 / 其余 4.5:1）。
3. **「进度填条 0px」是假红。** 一句没读的时候填条本来就该是空的。加上「已经读了 N>0 句」这个前提。

### 探针修对之后，抓到两条真的（都是本轮我自己引入的，已修）

| 问题 | 实测 | 根因 | 修法 |
| --- | --- | --- | --- |
| 「本次多久」小字看不清 | 3.67:1（10.5px，要求 4.5:1） | 我给它挑了 `#79857e`，比左边 `.tb-sub` 的 `#56625b` 浅 | 压到 `#667069` = **4.92:1**，仍比左边浅一档，主次没丢 |
| 深色下 ✕ 几乎看不见 | 2.2:1 | **特异度撞车**：`#taskBar .tb-close{color:#4a554f}` 带 id = (1,1,0)，压过 `body.dark .tb-close` 的 (0,2,1) → 深色规则根本没生效 | 深色那两条补上 `#taskBar`。旁边播放按钮的深色规则早就带着 id，只有我新加的这条漏了 |

两条都复量过：修完之后 390 与 1280 两档、亮/暗两态都不再报这两项。

### 两条**没修**的：确认是早就在的，不该混进这一轮

1. **主按钮白字压绿底 = 1.9:1**（P1）。`linear-gradient(135deg,#2bd4a4,#0fae7e)` + `#fff`
   是全应用的主 CTA 配方（`--grad`），「开始今日任务 / 下一题 / 继续任务 / 下一句」都是它，
   上一轮就已经在线上。手改等于改全站所有主按钮的视觉，**要他拍板**，不做顺手修。
   算术复核过：#2bd4a4 相对亮度 0.503，白字 (1.05)/(0.553)=1.90 —— 探针没算错。
2. **A-B / 循环 / 倍速 弹层在 390px 上溢出视口**（P2）。弹层 244px 宽、`left:50% + translateX(-50%)`，
   没有任何视口收边。**常规模式也溢出**（实测右边超出 39px：弹层右沿 429 vs 视口 390），
   任务模式只是把它从"超出右边"挪成了"超出左边 34px"。修法是让弹层改挂到条子上（窄屏 `position:static` + 左右 12px 收边），
   但那要同时动 3 个弹层 × 2 条栏 × 窄/宽屏，**风险面比这一轮整个 UI 改动还大**，单开一轮做。

### 全量从 13 分钟涨到 26.4 分钟，查了：不是底栏自激

`work/taskbar_loop_probe.mjs`（新）：不包装闭包函数（数不到），改数它**写出去的 DOM**——
MutationObserver 盯 `--task-bar-h` 的值真的变了没。结果：

| 静默 6 秒 | 翻 10 句 | 高度来回改号 | 帧数 |
| --- | --- | --- | --- |
| 写 0 次 | 写 0 次 | 0 次（单帧最大 0px） | 360 帧 / 6 秒 = 稳定 60fps |

底栏高度在 390px 上恒为 102.6px。**这个项目最坑的那类"读布局→改 class→重启过渡→无限循环"排除了。**
26.4 分钟没有归因（要跑一次基线全量才能定性，值 25 分钟），先记着别当"已经查清"。
