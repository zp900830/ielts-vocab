# 「继续学」目标篇口径统一（2026-10-12）

他原话（逐字）：

> 我看今天的任务开始是在第三章，第一句，我就从这个位置学习，并且已经学习了一部分了。
> 但我重新进入网页，点击「继续学」，他不是跳转到我在第三章已经学习的位置，而是去了第一章第一句。
> 能不能排查一下，这一块的逻辑，为什么老是有这种问题。

（附截图：横幅写「继续学《地球与生命》· 今天还剩 338 句」；第三篇卡片「今天 93/232 句」被红框圈出）

## 现象

今日任务起点在第 3 篇（衣食住行）第 1 句，且已从那里读了一部分（卡片：今天 93/232 句）。
重新进网页点「继续学」：横幅报「继续学《地球与生命》」（第 1 篇），点下去进第 1 篇第 1 句 ——
与「今天从第 3 篇第 1 句开始」直接矛盾。

## 根因：三层错位；同一个「该去哪一篇」有四个口径

**三层错位（本次报障的完整路径）**

1. **横幅按钮**（`app.js` `renderBanner`）：`openArticle(nextArticle())` —— `nextArticle()` = 「第一篇还没通读完的」
   （篇 1 只有 11% → 篇 1）。主文案取同一处的 `nextA`。**不看今日起点、不看今日进度、不看存档位置。**
2. **进篇后的队列**（`index.html` `todayPlan`）：`currentArticle = 0`、scope = [篇 1]；
   `manualStart`（在篇 3）不在 scope → 按篇刷句分支退化成「整篇从头重刷」→ 今日队列变成篇 1 的句子。
3. **位置恢复**（`enterTaskMode`）：存档位置在篇 3 ≠ `currentArticle`（0）→ 恢复条件不满足 →
   `goToNextTask(false)` → 落「篇 1 第一条未读」= 句 1。

**为什么「老是有」**：三层只是路径；真问题是「该去哪一篇」这个派生此前有**四处独立口径**，谁都不统一 ——

| 口径 | 定义 | 谁在用 |
|---|---|---|
| `nextArticle()` | 第一篇 `ever < total` | 首页横幅、我的 CTA |
| `todayArticle()` | 今天读得最多的篇 | 数据页「今天」块 / 收工 |
| `manualStart`（刷句起点） | 今天从哪开始（接力游标） | `todayPlan` 按篇装配、随身听今日任务、开始线 |
| `savedPos`（存档位置） | 上次读到哪句 | `enterTaskMode` 恢复、横幅「上次读到第 X 句」 |

每个入口各挑各的组合；修一处，别的入口照旧。同族报障史：

- 2026-09-26「记住进度」（横幅要显示上次位置）；
- 2026-09-28「已读句不恢复，第一下点就跳走」；
- 2026-10-10「随身听把 currentArticle 钉成 0」（篇 1）；
- 2026-10-12（同日早些）「随身听今日任务退化成篇 1 从头刷」→ 修法 = `manualRange()` 优先；
- 2026-10-12（本次）「首页继续学跳篇 1 第一句」。

## 修法：一个派生，全部入口都走它

**index.html（TASK 内，唯一派生）**

```js
function resumeArticle() {
  // ① 刷句模式：接力游标所在篇（用户明说「今天从这开始」；todayPlan 的按篇队列也从它起算）
  const ms = manualStartToday();
  if (ms && ms.gi >= 0) { const a = artOfSentGlobal(ms.gi); if (a >= 0) return a; }
  // ② 今天读得最多的篇（跨天首开无接触账时 todayArticle 给 -1）
  const a = todayArticle();
  if (a >= 0) return a;
  // ③ 都给不出 → -1（外壳退回「第一篇未通读完」的旧口径）
  return -1;
}
```

出口：`resumeArticle`（与 `todayArticle` 同段导出，注释标明「继续学」目标篇的唯一来源）。

**app.js（外壳兜底 + 三处接线）**

```js
function resumeTarget() {
  const na = nextArticle();
  if (na < 0) return -1;            // 六篇全完 → 维持「去词本」的旧口径，今日信号不抢先（W5-7 锁）
  const a = TASK.resumeArticle ? TASK.resumeArticle() : -1;
  return a >= 0 ? a : na;           // 有今日信号用今日，否则退回默认推进
}
```

- `renderBanner`：主文案 / 位置（`savedPosForArticle`）/ 按钮目标全部改用 `resumeTarget()`
  （渲染时算 `nextA0`；按钮点击时现算）——**文案报的篇与点下去的篇同源**。
- `meContent`（「我的」CTA 文案）+ `data-me-cta` 点击：同样 `resumeTarget()`。

## 没动的（避免顺手改坏）

- **六篇全完 → 「去词本」**（W5-7 锁，`m1-leftovers-2.spec.ts:134`）：`nextArticle() < 0` 时今日信号不抢先。
- 卡片点击、故事页「去读这一篇」——它们带**明确篇号**，不参与「该去哪一篇」的推导。
- 随身听今日任务（同日已修：`manualRange()` 优先）。
- `todayPlan` 的「书签不在本篇 → 整篇重刷」规则（2026-10-10 定）：那是「点卡片主动进某篇」的语义，保留。

## 踩到的坑（记一笔）

`renderBanner` 的结构是 `if (!hasPlan) {…} else { … const nextA = …; … }`，而
`el.querySelector('.b-go').onclick = …` 定义在**块外** —— onclick 里引用 else 块内的 `const nextA` 会
`ReferenceError: nextA is not defined`（点按钮**静默无反应**，body 不加 `task-mode`）。
旧代码此处本就是**现算** `nextArticle()`；修法照旧：点击时现算 `resumeTarget()`。
（本次先红后绿，第一次失败就是这个坑，用 `pageerror` 探针抓到的。）
