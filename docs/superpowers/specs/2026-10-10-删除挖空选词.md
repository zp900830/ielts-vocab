# 删除「② 挖空选词」：回一步制（2026-10-10）

他原话（逐字）：

> 然后我打算把所有选词填空相关的功能都删掉。目前：1. 非常打断阅读学习单词，2. 并不好用，反反复复 bug 特别多。
> 删掉之后你得把所有相关联的功能和规则都排查一下，是否需要同步做修改和优化。

## 他嫌的到底是什么

两条，分开说：

1. **打断**——① 通读的节奏是「一句一句往下读」，② 每次都要停下来看四个选项、点选、等判分、再自动推进。
   背着单词往下读的手感，被一串模态小卡切得七零八落。这不是 ② 一版两版能修的体验问题，是
   「做选择」这个动作本身就跟「快速刷词」（D10 原话）的节奏相冲。
2. **bug 多**——② 自 2026-09-22 两步制引入以来，环节最长：挖空渲染（词长保真）、浮窗定位（不压任务条）、
   候选生成（四层闸门）、判分与自动推进、答错补考、遍间小结……每一环都有自己的边角。
   「反反复复 bug」是这条链路的系统性成本，不是某个具体 bug。

## 新收工机制（② 没了之后，① 读满怎么收工）

挂在 `finishTask()` 上，两个触发点、三种落点：

1. **今天队列全读完**（`queueLeftToday() === 0`）→ 收工态「今天完成」：
   右侧两颗「看词本」（#tbNext → `#/words`）/「回首页」（#tbAgain）。
2. **额度读满、队列里还有没读的**（`todayQuotaDone() && 有剩余`）→ next() 的额度闸先进收工态
   「今天读够了」，按钮「继续读：扩回全局队列（`continueTodayQueue()`）→ 回 ① 通读态。
3. 无处可去时（队列空、无计划）→ 就地在卡片上完成，不再假装有下一步。

熟练度口径：`articleStat.progress = 通读完成度`（100% 满格 = 全篇读完），与 SRS 词槽无耦合。

## 附：图标字体与 supabase-js 改自托管（同日衍生，用户裁定）

**为什么**：jsdelivr 在国内常不可达，本机已复现 —— DNS 被代理工具劫持到 fake-IP 段
（`198.18.3.31`），系统代理一关（`scutil --proxy` 里 HTTPEnable/HTTPSEnable 全 0）直连必超时。
页面三个外链各自卡满 30s 才 `ERR_TIMED_OUT`，后果两条：

1. **门禁**：每页每次加载 +30s，全量跑到 48 分钟仍看不到头，且 a11y / touch-targets ×2 /
   icons / story / cloud-warmup ×2 / cloud-timeout / leftovers W6 共 9 条用例连锁误红 ——
   反推验证过：`#btnLoop` 盒子宽恒为 26px（padding 24 + border 2 + **内容 0**），
   即图标字形塌缩；带文字标签的 `#rateCycle`（"1x"）不塌，正是「字体没到手」的指纹。
2. **真实使用**：你自己的浏览器里图标与云端同步同样是坏的（代理一开一关就时好时坏）。

**落地**（`vendor/`，三件共约 540KB、gzip 后约 250KB）：

- `vendor/remixicon/`：取 registry.npmmirror.com 上 remixicon 4.5.0 包内的 `fonts/remixicon.css`
  与 `fonts/remixicon.woff2`（Apache-2.0，附 LICENSE）。CSS 只改 `@font-face` 一处：
  src 只留 woff2 —— 上游另带 eot/woff/ttf/svg 四种 2016 年前的格式，全带上要多背约 9MB。
- `vendor/supabase/`：`supabase-js-2.117.3.js`（MIT，附 LICENSE）—— 换成自托管那一刻镜像上
  `@supabase/supabase-js@2` 的最新版（UMD 218KB / gzip 56KB）。**代价：版本不再自动跟随 @2**，
  升级要手动换 vendor 里的文件 + 改 `index.html` 那一行。
- `index.html`：三个外链改本地路径；两条 jsdelivr `preconnect` 删除；字体 `preload` 保留
  （同源 + `crossorigin` 是 font preload 的规范要求，不是笔误）。
- 顺带收益：字体进了 SW 的 network-first 缓存范围（原先跨域请求被 SW 放行、不缓存）→ 离线也有字形。

**回归锁**：`icons.spec.ts` 源码级那条改成「只许引用本地 vendor + 页面里不许出现任何远端图标源
（`https?://…remixicon` 一律抓）+ 本地副本必须自称 4.5.0 + woff2 实体必须在」；
`build_site.mjs` 的白名单自检补 `.css` 与 CSS 内部 `url()`，防「CSS 在、woff2 不在」这种静默全塌。

## 附二：测试服务器从 python http.server 换 Node（同日衍生，用户裁定）

**为什么**：全量门禁在 4 workers 并发下成片红，且每次红的用例都不一样。根因是 python
`http.server` 的 `request_queue_size = 5`（backlog 只有 5）＋ HTTP/1.0 每文件新开连接：并发一上来

try/catch 静默吞掉 → `TASK.state()` 恒 null → 所有 `waitAppReady` 闸门挂满 120s。

**同端口 A/B 实测**（`scripts/stress-probe.cjs`，各加载 40 次）：

| 服务器 | 失败 | 耗时 |
|---|---|---|
| `python3 -m http.server 8931` | 23/40 | 3m25s |
| `node scripts/serve.cjs 8931 ..` | 0/40 | 5s |

**落地**：新增 `playwright-tests/scripts/serve.cjs`（HTTP/1.1 keep-alive、Node 默认 backlog 511、
异步 I/O、响应头 `Server: vocab-test-server` 供识别）。三处接线：`playwright.config.ts` 的
`webServer.command`、`utils/root-server.ts`（健康检查认 `Server` 头，清残留改
`lsof -ti tcp:8932 -sTCP:LISTEN` + SIGKILL，不再 pkill 匹配）、`scripts/ensure-server.cjs`。
压测探针留在 `scripts/stress-probe.cjs`（`PROBE_PORT=9000 node scripts/stress-probe.cjs` 可复跑）。

## 附四：W6 红灯的根因——`waitForFunction(async …)` 是假闸门（同日发现并修）

换 Node 服务器后页面秒开，`leftovers.spec.ts`「真实浏览器里 SW 注册成功、已激活」开始随机红
（先 5/6、后 2/6，红的轮次漂移 = 竞态）。逐帧探针（内页 5ms diff 采样 + register/controllerchange/
导航事件 + 全量 console）锁定的证据链：

- 失败轮次里 `register()` 从未 resolve、`instState` 恒 null、`controllerchange` 从不触发；
- 但 `page.waitForFunction` 在 `reg:true, act:false` 那一刻就放行了；
- 读 Playwright 1.63 注入脚本源码：`const success = predicate(); if (success) { fulfill(success); return; }`
  —— 谓词是**同步**求值的，**async 谓词返回的 Promise 对象恒 truthy ⇒ 第一次轮询就放行**；
- 语义实验（5 种谓词）确认：`async () => false` 3ms 就"通过"；`page.evaluate` 才真等 promise。

**即**：那条写着「条件等待：本页 scope 的注册已激活（不 sleep）」的闸门等于没有，测试实际是
「evaluate 执行时机 vs SW 激活时机」的毫秒级赛跑。python 服务器时代 `goto` 慢、SW 早已激活，
靠运气恒绿；换 Node 后赛跑窗口露出来。

**修法**：新增 `waitSwActive(page)` 辅助（用 `expect.poll` —— 其回调签名是 `() => T | Promise<T>`，
会真等），替换同文件 4 处同类假闸门（W6 主用例 / 高重复 reload / 断网 reload / 断网无缓存）。
修后 `--repeat-each=12` **12/12 绿**（修前 5/6 红），整个 `leftovers.spec.ts` 12/12 绿。
