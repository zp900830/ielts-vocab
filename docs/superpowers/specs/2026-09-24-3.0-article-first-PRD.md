## 1. 产品定位

### 1.1 一句话

3.0 把 v2.0 里分散在两个应用（情景训练 + 影子跟读）里的学习行为**合并到一个产品**里，核心路径只有一条：

> **阅读文章 → 理解文章 → 跟读/朗读 → 反复熟悉文章 → 在不同语境中掌握文章中的单词 → 真正掌握单词**

### 1.2 设计总纲

| 原则 | 含义 |
|------|------|
| **文章是学习主线** | 六篇大文章是全部学习行为的入口和容器，不是「阅读功能」 |
| **单词是学习结果** | 单词从文章学习过程中自然沉淀出来，不作为一级入口 |
| **信息层级** | 文章 > 学习任务 > 学习进度 > 单词 > 数据 |
| **产品形态** | 「以文章为载体的英语学习系统」，不是「背单词 App + 一个文章功能」 |
| **复用不重造** | 视觉体系继承情景训练（`index.html` 现有 tokens），播放交互继承影子跟读（`shadow/index.html` 现有逻辑），任务模式逻辑继承 v2.0 的两步制引擎 |

### 1.3 核心学习路径

```
首页选文章 → 进入文章任务模式
                        ↓
              ① 通读（一步一停 · 逐句跟读）
                        ↓
              ② 挖空选词（语境中检验）
                        ↓
              日常：随身听反复磨耳 → 全屏阅读精读 → 单词本复习
                        ↓
              文章熟练度 ↑ → 单词掌握数 ↑ → 下篇文章
```

### 1.4 学习目标

| 目标 | 量化口径 |
|------|---------|
| 持续学习 6 篇核心文章 | 全部进入「已学完」态：**每句至少读过一次 + ② 答过一遍**（判据见 §9.4，注意不是「通读遍数」—— 遍数没有记账） |
| 熟悉度 / 理解度 / 朗读熟练度 | 每篇文章一个 0–100% **熟练度**分数（由通读次数 + ② 正确率 + 跟读次数合成，见 §9.2） |
| 真正掌握单词 | 词状态机（已见面 → 文中可辨 → 义项直连 → 已毕业）沿用 v2.0 引擎，全 3245 词 |
| 看到自己的进度和掌握情况 | 首页卡片 + 学习数据页 + 单词本，三个层级都有实时数字 |

## 2. 信息架构与页面框架

### 2.1 整体布局

**左侧固定导航 + 右侧内容区域**，桌面 / 平板 / 手机三档：

```
┌─────┬──────────────────────────┐
│     │                          │
│ 导  │      内容区域             │
│ 航  │   （当前一级页面）        │
│     │                          │
│ 4项 │                          │
└─────┴──────────────────────────┘
桌面 ≥ 1024px：左侧固定侧栏 220px（4 项，图标 + 文字；底部一条分割线 + 「我的」一行）
平板 701–1023px：左侧收窄侧栏 180px（图标 + 文字收窄）
手机 ≤ 700px：底部 TabBar（4 项 + 「我的」，共 5 格）
```

### 2.2 一级导航（4 项 + 底部「我的」一行；不加）

| # | 名称 | 图标 | 路由 | 页面职责 |
|---|------|------|------|---------|
| 1 | **首页** | 🏠 `ri-home-5-line` | `#/home` | 六篇文章卡片 + 「今天该做什么」 |
| 2 | **学习数据** | 📊 `ri-bar-chart-2-line` | `#/stats` | 学习总览 / 文章 / 单词 / 趋势四块 |
| 3 | **单词本** | 📖 `ri-book-2-line` | `#/words` | 按文章关联的单词列表 + 详情 |
| 4 | **随身听** | 🎧 `ri-headphone-line` | `#/listen` | 播放卡片 + 展开全屏阅读 |

**「我的」不再是一级导航**（2026-09-24 用户改口径）：改成**侧栏底部一条分割线 + 下面一行**（未登录显示「登录」按钮；
已登录显示头像 + 账号），点它**向上弹「我的」浮窗**（账号 / 学习摘要 / 当前状态 / 数据管理 / 主题 / 口音 / 音色 / 计划设置，见 §8.1），
不再是切页。手机端这一行就是底部 TabBar 的**第 5 格**。所以导航是 **4 项 + 1 行**。

**明确不加的页面**：使用方法、性能与错误、帮助中心、关于产品、设置大杂烩 —— 与核心学习流程无关的任何入口。设置里能留的只有：每日分钟数、日界、新词开关（沿用 v2.0 的三个旋钮，收进「我的」浮窗里，不再单独占一级页面）。

### 2.3 首次进入（还没有计划）

**2026-09-24 定**：没计划**也能进任务模式** —— 页面给一个空状态 + 跳配置的入口，既不堵门、也不装死。

| 场景 | 行为 |
|------|------|
| 打开首页 | 照常可浏览六张卡片（全「未开始」态），不拿设置屏堵门 |
| 点卡片 | **照常进入该篇任务模式**（正文可读、可自由跟读）；**任务条那一格换成空状态**：「还没有学习计划 · 去设置每天读多久」→ 点了跳配置（v2.0 的设置屏）。⚠️ v2.0 的 `enterTaskMode()` 在 `!plan` 时**直接 return**，3.0 要把这条改成「照常渲染 + 空状态」 |
| 进「学习数据」 | 没计划时整页就是设置屏（§5.2） |
| 进「随身听」 | 不要求有计划，可以直接听（六篇任选） |

### 2.4 一级页面之外的全部入口（穷举，防止悄悄长出新页面）

| 入口 | 形态 | 来自哪 |
|------|------|--------|
| 词库抽屉 | 正文右侧边标签 → 抽屉 | 影子跟读 `#panel` / `#edgeTab` |
| 单词释义卡 | 点正文里的词 → 浮窗 | 影子跟读 `openPop` / `#pop` |
| 快速跳转 | 点标题胶囊 → 选卷 + 输句号 | 影子跟读 `#jumpPop` |
| 今日面板 | …… **3.0 不再需要**：它承载的「今天/计划/词本」三屏已被拆成一页首页 + 一页学习数据 + 一页单词本 | — |

> 这条是给实施时的护栏：**除上表之外不再新增浮层/页面**。

### 2.5 技术底座

| 项 | 决策 | 理由 |
|---|------|------|
| **部署路径** | **3.0 做新站点，不动现有两个应用**：`/app/`（新目录，草案）承载 3.0；`/`（情景训练）与 `/shadow/`（影子跟读）**原样保留、照常可访** | 2026-09-24 定：旧版内容是资产，不做替换、不做「丢掉」（§11.3）。⚠️ 是否改用**独立域名**（如 `3-0.ielts-vocab.bond`）见 §14 |
| 旧应用保留 | `/` 与 `/shadow/` 一行代码不动 | 3.0 与它们**并存**，互不依赖 |
| 单页 vs 多页 | 仍然是单页 HTML + hash 路由（`#/home` 等），不引入框架 | 沿用现有架构（`index.html` 4636 行 / `shadow/index.html` 6725 行，都是零依赖单文件）。**3.0 主要是把影子跟读那套运行时（6725 行）搬过来 + 加外壳与两个新页面，预计 7000–9000 行**；真实体量以实施为准，若超 10000 行则拆 `app.js` / `app.css` 两个外部文件（同 `shadow/js/plan-engine.js` 的做法，加进构建白名单） |
| 数据层 | 沿用 `ielts.shadow.v2`（`ROOT2` 事件流 + 词状态机引擎 `plan-engine.js`） | v2.0 的间隔引擎、词状态机、事件流重放**原封不动搬过来**，只换驱动方式。⚠️ **localStorage 是同一浏览器、同源共享的**：3.0 在 `/app/` 下的 `localStorage` 与 `/shadow/` **不是同一份**（路径不同不影响 origin，同源就是同一份！）—— 见下方注释 |
| 发布白名单 | 新文件（`app/index.html` 等）必须同时加进 `scripts/build_site.mjs` 的 `FILES` | 该文件是**显式白名单**，没列进去的文件公网不可见、且构建自检会直接失败（见 AGENTS.md） |
| PWA | 把主站的 service worker + manifest 搬过来 | ⚠️ **影子跟读目前没有 service worker**（`grep serviceWorker shadow/index.html` = 0 命中），主站有 —— 3.0 要继承的是主站那一套 |

> **关于同源共享（重要，别踩）**：`ielts-vocab.bond/app/` 与 `ielts-vocab.bond/shadow/` **同源**，
> 所以 3.0 和影子跟读会**共用同一份 `localStorage`**。好处是老用户的进度直接续上（§12.1 的无缝升级成立）；
> 风险是两边同时在跑时，后写的会覆盖先写的。
> 处置：3.0 **继续用 `ielts.shadow.v2` 这个 key、不改 schema**（读写都兼容），
> 并在 `VERSION`/PRD 里写明「3.0 与影子跟读共用进度，同时开两个标签页可能互相覆盖」。

## 3. 首页 · 六篇文章卡片

### 3.1 页面结构

```
┌──────────────────────────────────────────┐
│  顶部问候区（Hi / 今天读多久 / 继续/开始按钮）│
├──────────────────────────────────────────┤
│  ┌────────┐ ┌────────┐ ┌────────┐        │
│  │ 文章 1  │ │ 文章 2  │ │ 文章 3  │       │  ← 6 张卡片
│  └────────┘ └────────┘ └────────┘        │     桌面 3 列
│  ┌────────┐ ┌────────┐ ┌────────┐        │     平板 2 列
│  │ 文章 4  │ │ 文章 5  │ │ 文章 6  │       │     手机 1 列
│  └────────┘ └────────┘ └────────┘        │
└──────────────────────────────────────────┘
```

### 3.2 文章卡片数据（每张 4–5 个数，不堆砌）

按「帮用户判断这篇文章学得怎么样了」挑，每组只留最能说话的：

| 数据 | 来源 | 说明 |
|------|------|------|
| **文章标题**（中 + 英） | `SECTIONS[n].title` / `TIT_EN` | 一行中文 + 一行小字英文 |
| **熟练度** | §9.2 公式 | 一根 0–100% 的进度条 + 百分比数字，是卡片**视觉最重**的元素 |
| **当前阶段** | 派生（§9.4） | 一枚状态胶囊：`未开始` / `通读中` / `② 可答题` / `已学完` / `熟练` |
| **单词掌握** | **需新增** `countStagesOf(article)` | `已毕业 X / 全篇 Y 词`。⚠️ 现有 `countStages()` **只统计全局、没有按篇能力**（`for (const k in ROOT2.state.words)` 一把梭），要新建一张「词 → 篇章」索引，见 §9.5 |
| **最近学习** | `state.sents` 最后接触时间 | `3 天前` / `今天`，相对时间 |

> **不做的**：学习次数、跟读次数、已学习天数 —— 这些在「学习数据」页里看，卡片上放不下也不该放。

### 3.3 卡片状态视觉（4 档）

| 状态 | 判据 | 视觉 |
|------|------|------|
| **未开始** | `sentDone = 0` 且 `quizDone = 0` | 灰底 + 虚线进度条 + 半透明标题 |
| **学习中**（通读 / ②） | 有进度但未满 | 正常卡片 + 薄荷进度条 + 状态胶囊 |
| **已学完** | 通读 ≥1 遍 + ② ≥1 遍 | 进度条满 + 绿色胶囊 `已学完` |
| **熟练** | 熟练度 ≥ 80% | 进度条换金色渐变 + `熟练` 徽章 |

### 3.4 点击行为

点卡片 → **进入该文章的任务模式页面**（§4），不是阅读详情页。

### 3.5 顶部「今天该做什么」

首页顶部一条窄横幅（不是弹窗），内容：

- 还没建计划 → 「设置你每天的学习时间」按钮 → 展开设置屏（复用 v2.0 的 `renderSetup`）
- 有计划 & 今天没做完 → 「继续学《XX》· 还剩 N 句」 + 开始按钮
- 有计划 & 今天做完了 → 「今天的量读完了 · 多读了 N 句」（沿用 v2.0 的如实口径）
- 有计划 & 连续 N 天 → 「连续 N 天 · 已毕业 M / 3245 词」

## 4. 文章任务模式（进入卡片后）

### 4.1 整体结构（参考情景训练阅读器 + 影子跟读任务模式）

```
┌──────────────────────────────────────────┐
│ ← 返回首页 │ 文章标题 │ 卷/段筛选        │  ← 顶栏
├──────────────────────────────────────────┤
│                                          │
│       当前学习任务内容区                  │
│       ① 通读态 = 正文 + 高亮当前句        │
│       ② 挖空态 = 正文里挖空 + 浮窗选择    │
│                                          │
├──────────────────────────────────────────┤
│  任务条（一条浮空玻璃卡）                  │  ← 底部固定
│  进度 n/N + 位置条 + 放这一句/下一句/…   │
└──────────────────────────────────────────┘
```

- **顶部**：文章信息（标题 + 卷名）+ 筛选（按卷/段快速跳，沿用 `#jumpPop`）
- **中间**：任务内容（① 通读 / ② 挖空，两态切换）
- **底部**：任务条（v2.0 的 `#taskBar` 一条通栏、三态换内容、不藏控件）

### 4.2 复用 v2.0 任务模式的完整逻辑

以下**全部继承 v2.0 已上线的实现，不重写**：

| 能力 | v2.0 实现 | 3.0 改动 |
|------|-----------|---------|
| 一步一停播放 | `playFrom` 跳过预取 + `taskSentenceFinished` 完成计数 | 无改动 |
| 那颗键担两义 | 「放这一句」→「下一句」+ 点过整趟不变 | 无改动 |
| 放完不自动挪高亮 | `taskSentenceFinished` 只记完成、不 `goToNextTask` | 无改动 |
| **② 挖空答题** | `buildQuiz` 四层闸门 + 辨析干扰项 + 补考一次 | **引擎不变，UI 重做**：从「底部题卡」改成「**文内挖空 + 浮窗选择**」（§4.4） |
| 遍间小结（①→②） | `renderPassSummary` 三个数字 | 保留，它就是 ② 的**入口提示**（§4.4「入口」） |
| 收工态 | 「今天完成 · N 句 · M 词晋升」 + 看词本 | 按钮改为「回首页」+「看词本」（跳单词本页） |
| 续读 | 刷新后任务条变续读条「今天 N 句 / 接着做」 | 无改动 |
| 队列排程 | `ShadowPlan.assemble`（三池 + 分钟预算 + 保温） | **驱动从「全局队列」改为「按篇队列」**：进入第 N 篇时 assemble 只排这一篇的句（§9.3） |

### 4.3 ① 通读态（正文阅读）

- 正文布局沿用影子跟读的 `#art`：段（`.para`）→ 句（`.sent`），行内 `[[词:形式]]` 标记 + 点词弹释义卡（`openPop`）
- 译文开关 / 行内词义开关 / 口音+音色切换 → 顶栏（沿用 `header.topbar` 的控件，但收窄为一条）
- 当前句高亮 `.playing` + 自动滚动跟随（`scrollIntoView block:center`）
- 播放条 = **任务条那一条**（不是底部另一个 audiobar），v2.0 的做法

### 4.4 ② 挖空答题（文内挖空 + 浮窗选择）

> **2026-09-24 改口径**：② 不再是「底部弹出一张题卡」，改成**挖空直接长在正文里、选择用浮窗**。
> v2.0 的底部题卡（`#taskCard` + `renderQuiz`）形态作废；出题引擎（`buildQuiz` 四层闸门 / 四选一 /
> 补考一次 / 辨析干扰项）**原封不动**，只换承载它的 UI。

```
① 通读完成
    ↓  （遍间小结卡提示「进入答题」）
② 挖空态：正文里把本遍的目标词挖成空
    ↓  （点空 / 点任务条的「下一题」）
浮窗答题卡（四选一，锚在那个空上）
    ↓  （选完）
空被填上：对=绿字 / 错=红字＋正确答案，错的再摊辨析表
    ↓  点「下一题」
定位到下一个还没答的空 → 弹浮窗 …… 答完 → 小结 → 收工
```

| 项 | 规格 |
|----|------|
| **挖空位置** | 正文对应句里的**目标词位置**（`.sent` 内联 `<span class="qz-blank">`），不另起容器 |
| **空的样子** | 下划线 + 按被遮词形给宽度（沿用 `maskSplit` 口径）；三态：未答 / 答对 / 答错 |
| **点空** | 弹出**浮窗答题卡**，锚在该空附近（复用 `.prog-tip` 那套玻璃浮层），里面 4 个选项 + 「这题有问题」 |
| **选完** | 浮窗收掉 → 空里填上所选词；答错就地摊开辨析表（原来那套 `revealNote`） |
| **「下一题」** | 底部任务条那颗键：滚到**下一个未答的空**（居中）+ 自动弹浮窗；没有下一个 = 进小结 |
| **「这题有问题」** | 从题卡头部移进浮窗 |
| **「回看句子」** | **去掉** —— 句子就在眼前，不需要"回看" |
| **进度** | 任务条仍报 `② 挖空答题 3/24`（同一个 n/N 口径，见 §10.3 数字唯一性） |
| **键盘** | 浮窗打开时 1–4 选择、Esc 关浮窗；`→` = 下一题 |

**入口（两条，都要做）**

| # | 入口 | 行为 |
|---|------|------|
| 1 | **通读完成即提示** | ① 走完 → 遍间小结卡（沿用 `renderPassSummary`）→「开始答题」按钮 → 进 ② 态，正文立刻挖空 |
| 2 | **首页卡片直达** | 首页卡片上，**通读已完成**（= 该篇每句都读过至少一次，即 §9.4 的 `everRead = 全篇句数`）的篇目多一颗「答题」按钮，状态胶囊同步显示「可答题」→ 点了直接进该篇 ② 态 |

> 入口 2 的意义：今天只想做题、不想通读，也不该被挡在门外。直达 ② 时批次用当天 `assemble` 的
> items 现建（与"① 后进 ②"同源），**不要求先跑一遍 ①**。

### 4.5 任务模式里点句 = 一步一停（2026-09-24 定）

**点正文里任意一句 = 只放那一句**（`playFrom`，高亮跟过去），依旧是「放完不自动往下走」——
和「放这一句」那颗键同一套口径，**不切换成连播**。

> 早前草稿写过「点句 = 在当前位置改为自由阅读（自动连播）」，**2026-09-24 用户否掉了**：
> 任务模式里就保持一步一停，最稳、不会意外连播。
> 想连播精读整篇 → 去「随身听」（§7），那是它唯一的职责。

## 7. 随身听

### 7.1 定位与融合方式

> **视觉和整体页面结构 → 情景训练**
> **播放条交互 → 影子跟读**

具体：
- 页面骨架 = 情景训练的 `#lsPanel` 全屏浮窗风格（居中大卡片 + 玻璃底）
- 播放控制 = 影子跟读的播放条交互（点句即读 / 单句循环 2·3·5 遍 / AB / 倍速 / 书签 / 位置条）

### 7.2 播放卡片（默认态）

```
┌──────────────────────────────────┐
│      ┌──────────────────┐        │
│      │   当前文章封面区   │        │  ← 篇名 + 卷名 + 一句正在播的原文
│      │   正在播…          │        │
│      └──────────────────┘        │
│                                  │
│   ◄ 上一篇    ▶ / ⏸    下一篇 ►   │  ← 播放控制（影子跟读逻辑）
│                                  │
│   ────────●────────────         │  ← 句级位置条（可拖）
│   第 12 / 339 句 · 还剩 23 句    │
│                                  │
│   循环 3 遍 · AB · 1x · 书签     │  ← 影子跟读的四个弹层按钮
│                                  │
│      [ 点击展开全文阅读 ]          │
└──────────────────────────────────┘
```

### 7.3 展开全屏阅读

点卡片任意处 → 展开全屏阅读弹窗：

- 正文 = 影子跟读的常规模式阅读页（`#art` 段→句结构 + 行内词义 + 当前句高亮 + 自动滚动）
- 播放条 = 底部玻璃播放条（影子跟读 `.audiobar`，含上一句 / 播放 / 下一句 / 循环 / AB / 倍速 / 书签 / 快速跳转）
- 关闭 → 收回随身听播放卡片（**不是**退回首页）

完整路径：

```
随身听 → 播放文章 → 点击卡片 → 全屏阅读 → 关闭 → 返回随身听
```

### 7.4 连续播放

- 默认连播：当前句播完自动进下一句（影子跟读的 `launch` 链，**不走**任务模式的一步一停）
- 篇末自动切下一篇（六篇循环），也可以在卡片上手动 ◄ / ► 切换
- Media Session 锁屏续播 + Wake Lock（v2.0 已实现，原样搬）

### 7.5 与首页的联动

随身听播的文章 = 「最近在学的那篇」默认值；用户切了篇之后，首页卡片上的「最近学习」也会跟着更新（读同一个 `state.sents` 的 `lastContactAt`）。

### 7.6 随身听与任务模式**分开记账**（2026-09-24 定）

**两套数各算各的，不混：**

| 来源 | 记什么 | 进不进熟练度 | 界面读它的地方 |
|------|--------|-------------|--------------|
| **任务模式**（① 通读 / ② 答题） | **精读次数**（每篇一个累计值） | ✅ 进（§9.2 的 25% 那一项） | 任务条、首页卡片、学习数据页 |
| **随身听** | **收听数据**（每篇听了多少句 / 多长时间） | ❌ 不进 | 只在「学习数据」页有独立一块 |

- 两套都仍走引擎的 `contact` 事件（**一天一句只记一次接触**是 §9.1 的引擎口径，动不了、也不会虚高）
- 但「**精读次数**」只数任务模式里的完成（`taskSentenceFinished`），随身听的一律不往里算
- 于是「口袋里挂着连播」刷不出精读次数、也刷不动熟练度 —— 想提熟练度只能坐下来精读

> v2.0 的老口径是「自由模式播放也 `recordRep`」，两套混在一起、还导致毕业门槛能被口袋连播刷穿；3.0 拆开。

## 9. 数据模型与进度体系

### 9.1 底座不变

沿用 v2.0 的 `ielts.shadow.v2`（`ROOT2`）+ `shadow/js/plan-engine.js`：

- **词状态机**：`seen → recognized → owned → graduated`（+ `leech` 重点词通道）
- **事件流**：`contact / quiz / stage / relearn / dayplan` append-only，重放派生一切
- **间隔排程**：`wordInterval(reps)` 按接触次数排 `due`，毕业词 14 天回池保温
- **日账**：`daily[day]` 的 `sentDone / quizDone / correct / promote / minutes`

3.0 只加一个维度：**按篇统计**。

### 9.2 文章熟练度（新派生字段）

```
熟练度(article) =
    通读完成度 × 40%      ← min(该篇「每句至少读过一次」的句数 / 全篇句数, 1)
  + ② 正确率 × 35%       ← 该篇 quiz 正确数 / 该篇 quiz 总数（该篇还没有 quiz 记录时这一项记 0）
  + 精读重复度 × 25%     ← min(该篇「精读次数」/ (全篇句数 × 2), 1)
                          ⚠️「精读次数」只数**任务模式**里的完成；随身听不计（§7.6）
```

> 「× 2」意思是：每句平均精读 2 遍就算这一项拉满 —— 再多放不额外加分（避免刷次数）。
> 熟练度 ≥ 80% 且已学完 → 卡片显示 `熟练` 徽章。
> **三个权重是草案值**，上线后按六篇的真实分布再调（§14 第 2 条已确认「先按这组跑」）。

### 9.3 按篇队列（assemble 的驱动变化）

| | v2.0 | 3.0 |
|---|------|-----|
| 队列来源 | 全局排（六篇混排，三池 + 分钟预算） | **按篇排**：进入第 N 篇的任务模式时，assemble 只在这一篇的句子里排 |
| `assemble` 接口 | `assemble(state, {now, todayMinutes, rate, secNew, secReview, wordsOf, totalSents, boundaryHour, plan})` | **加一个 `scope`**：`assemble(state, {…, scope: Set<全局句号>})` —— 只从 scope 里挑句。**这是本次唯一的引擎改动**（`plan-engine.js` 纯加参数，不带 scope 时行为与 v2.0 完全一致，老测试不受影响） |
| `plan.newPerDay` | 按全局词数折算 | 按当前篇的词数折算（同样靠 scope 收窄） |
| 保温 / 到期复习 | 全局混排 | 只在 scope 内排（别的篇的到期词**不进**今天的队列，留到点进那篇时再排） |
| 事件流 | 不变 | 不变（contact / quiz 照推，引擎重放不区分篇） |
| 毕业判据 | 不变（12 次接触 + 1 次 ② 答对） | 不变 |

> ⚠️ 早前草稿写的「引擎不改、改调用方」**不成立**：`assemble` 的候选集来自 `state.words` 全量，
> 调用方没法在外面收窄而不破坏分钟预算（在外面 filter 会把预算算空）。所以老老实实加 `scope`。
>
> **为什么改**：v2.0 的全局队列适合「跟着排程走」的被动学习；3.0 的核心是「用户选一篇文章、把它学透」，按篇排让用户点进一篇文章时看到的是**这篇自己的**进度 n/N，而不是全局排程里混着六篇的 n/N。
> 代价：断更后欠的句子不再「顺延到全局队列」，而是「留在那篇文章里」—— 想起来哪篇没学完就点哪篇，这是 3.0 更鼓励的行为。

### 9.4 首页卡片的数据来源（全从 ROOT2 派生，不新增存储字段）

⚠️ **注意**：`sentDone` / `quizDone` 是**日账里的全局计数**，不能拿来判「某一篇学到哪了」。
按篇要用下面这三个派生量（都由 `state` 现算，不写盘）：

| 派生量 | 算法 |
|--------|------|
| `everRead(篇)` | 这一篇的句子里 `state.sents[i].lastReadAt > 0` 的条数（读「有没有碰过」，不是「今天读没读」） |
| `quizOf(篇)` | 事件流里 `type='quiz'` 且该句属于这一篇的条数 |
| `quizOkOf(篇)` | 同上，`ok=true` 的条数 |

| 卡片数据 | 计算 |
|---------|------|
| 熟练度 | §9.2 公式 |
| 当前阶段 | `everRead = 0` → `未开始`；`everRead > 0` 且 `quizOf = 0` → `通读中`；`everRead = 全篇句数` 且 `quizOf = 0` → `② 可答题`；`quizOf > 0` 且未满一遍 → `② 做题`；通读满 + ② 满一遍 → `已学完`；熟练度 ≥ 80% → `熟练` |
| 已毕业 X / 全篇 Y | `countStagesOf(篇)`（§9.5） |
| 最近学习 | 这一篇 `state.sents` 的 `max(lastReadAt)` 转相对时间 |

### 9.5 要新增的三张派生索引（实施时的清单）

现有代码里**没有**按篇统计的能力，这三样必须新建（都放 `plan-engine.js`，纯函数、可单测）：

| 名称 | 作用 | 为什么必须新建 |
|------|------|--------------|
| `wordArticle(word)` | 词 → 它出现在哪几篇 | `VOCAB` 只有词条，没有篇章归属；句子里的 `[[词:形式]]` 标记才是真来源 |
| `countStagesOf(article)` | 按篇的词状态计数 | 现有 `countStages()` 只扫全局 |
| `articleScope(article)` | 该篇的全局句号集合 | 按篇队列要喂给 `assemble`（§9.3） |

> 三个都是「句子 → 篇章」的同一个映射派生出来的，实现时一次建好、共用。

## 11. 不做什么

### 11.1 页面不做的

| 不做 | 理由 |
|------|------|
| 使用方法 / 帮助中心 / 关于产品 / 性能与错误 | 与核心学习流程无关 |
| 单独的「设置」一级页面 | 三个旋钮收进「我的」浮窗 |
| **脱离文章**的背词形态（卡片翻转 / 拼写测试 / 无语境刷题） | 3.0 核心是文章语境中习得。② 的四选一**保留**，但它长在文章里、锚在具体句子上（§4.4） |

| AI 对话 / 写作批改 | 超出当前范围 |

### 11.2 功能不做的

| 不做 | 理由 |
|------|------|
| 自由选篇组合成「自定义课程」 | 六篇就是六篇，不拆不组 |
| 篇章内句子级别「跳过不学」 | 每句都要过一遍，② 出题的底线 |
| 导入自定义文章 | 内容是核心资产，不做 UGC |
| 离线整包下载 | PWA + Cache Storage 够用（v2.0 已有） |

## 12. 迁移与兼容

### 12.1 用户数据（3.0 与旧版**同源共用**）

⚠️ `/app/`、`/`、`/shadow/` 是**同一个 origin**，`localStorage` 是**同一份**。所以：

| 场景 | 处理 |
|------|------|
| 影子跟读老用户 | 3.0 读同一个 `ielts.shadow.v2`，事件流重放后词状态 / 日账 / streak / 书签全在 → **天然无缝**，不需要迁移代码 |
| 同一个浏览器开两个标签页（3.0 + 影子跟读） | ⚠️ 两边都会写同一个 key，**后写的覆盖先写的**。不做锁（单人使用，成本不划算），只在文档与 `VERSION` 里写明 |
| 主站老用户（`learning_data` 表 / 22 章故事进度） | **与 3.0 无关**：3.0 不读主站数据，主站也不读 3.0 的。两套进度各自独立 |
| v1.x 用户（只有 `ielts-task-plan` / `ielts-task-progress`） | 走 v2.0 的迁移路径（`ShadowPlan.migrate`），3.0 不再单独做 |

### 12.2 部署（3.0 = 新路径，旧版一行不动）

| 步骤 | 内容 |
|----|------|
| 1 | **开分支开发**（AGENTS.md 纪律：`agent/<name>-3.0-<date>`，不直接动 `main`）。`/` 与 `/shadow/` 全程不动 |
| 2 | 新建 `/app/` 目录：`app/index.html`（+ 需要时的 `app/app.js` / `app/app.css`）；**全部加进 `scripts/build_site.mjs` 的 `FILES` 白名单**，否则公网 404 且构建自检直接失败 |
| 3 | 数据：把 `shadow/data/{sections,vocab,chapters}.json` **复制**成 `app/data/`（构建期复制，不手改）；`SHADOW_DATA_VER` 跟着 `shadow/` 那份走 |
| 4 | 本地全量 E2E 绿 + `validate_data.py` PASSED（AGENTS.md 的「完工前 3 件事」） |
| 5 | 合并到 `main` → EdgeOne 自动部署。线上验证：`/` 与 `/shadow/` 未受影响、`/app/` 是 3.0 |
| 6 | 切 tag `v3.0.0`，更新 `VERSION` 文件 |

**回滚预案**

| 情况 | 动作 |
|------|------|
| 3.0 有问题，先别让人进 | **把入口摘掉就行** —— 3.0 是新路径，旧版 `/` 和 `/shadow/` 压根没变。要么 `revert` 掉 3.0 那个 merge，要么在 EdgeOne 上把 `/app/` 下线 |
| 只想下线 3.0 的某一屏 | 每屏都是 hash 路由（`#/home` `#/stats`…），改路由表 + 重新部署即可 |
| 数据层出问题 | 与 v2.0 同一 key、同一 schema，**不需要数据回滚**；真出问题用「导出备份」先存一份再修 |

> ⚠️ 不能写「`git checkout v2.0` + 重新部署」：那是 detached HEAD，EdgeOne 只监听 `main`，根本不会部署。
