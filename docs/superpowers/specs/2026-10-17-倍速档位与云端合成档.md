# 倍速档位 7 档 + 云端合成档位映射（2026-10-17）

## 报障

用户：「0.75 倍速，云端语音无法正常加载出来，其余正常。参考其他同类产品，看倍速要改成几个档位，目前感觉明显不够用。」

两件事：
1. 0.75x 是唯一「后加的慢速档」，云端整句合成失败（其余 1 / 1.25 / 1.5 正常）。
2. 现有 4 档（0.75 / 1 / 1.25 / 1.5）两端都不够：慢速没有 0.5（生词多的首读），快速没有 1.75 / 2（复习速刷）。

## 档位依据

同类产品（每日英语听力、不背单词、墨墨、微信读书、YouTube、Audible）常规区间落在 **0.5 ~ 2.0**；
少数（每日英语听力、Audible）提供自定义/滑块。背单词是逐句听读，预设太密会让菜单变长、误点变多，
太疏又两端不够用。

**2026-10-17 用户定版：预设 5.0 / 3.0 / 2.0 / 1.5 / 1.2 / 1.0 / 0.8（从快到慢，1.0 居中）
+ 自定义 0.1 ~ 5.0、步进 0.1。**

## 根因与修法

### 根因（按代码与接口契约推断，服务端源码不在本仓库）

`_fetchTTS` 把 `rate` 原样发给 `functions/v1/tts`。1 / 1.25 / 1.5 三档长期正常，
0.75 是后加的慢速档 → 服务端没有跟着支持（沙箱到 `*.supabase.co` 的 TLS 被拦，无法实测，
但「只有新档失败」这一指纹足够定位到档位取值本身）。

### 修法：变速从「合成参数」搬到「播放层」

- 新增 `cloudSynthRate(r)`：云端只按 **1 / 1.25 / 1.5** 三档请求，其余档位取「播放倍率最接近 1」的原生档
  （对数距离：0.5/0.75 → 1x；1.75/2 → 1.5x）。
- `play()` 设置 `<audio>.defaultPlaybackRate` + `playbackRate = 目标档 / 合成档`，
  `preservesPitch = true`（变速不变调；媒体加载算法会把 `playbackRate` 重置回 `defaultPlaybackRate`，两个都要写）。
- 缓存坐标（`r2|voice|合成档|text`）改按**合成档**记：0.5 与 0.75 共用一份 1x 音频，
  1x 与 0.75 之间切换不再各合成一遍；`synth` 与 `play` 的 key 必须逐字一致。

### 顺带修的一个隐患

`CLOUD.play` 的 30s 定时器原本兼作「合成 + 播放」总超时。0.5x 把句子拉长一倍，
长句（>30s）会在音频正常播放时被掐断、误降级本地。改为：合成完成即清掉，换挂 300s 播放兜底
（只在 `onended` 真的不来时救场）。

## UI

菜单单列竖排（照用户给的参考实现），8 项靠 `max-height: min(72vh, 400px)` + 滚动兜住小屏；
单句循环菜单只有 3 项，保持原样。

「自定义」打开同锚点的滑块面板（0.1~5.0，`step=0.1`）：拖动时只更新跟手气泡，
`change`（松手）才落 `setRate` + `savePref`，避免每 0.1 都写盘/重绘。面板与预设列表互斥，
同在 `.rate-wrap` 内，点外部 / Esc 仍由 wrap 的 `open` 状态统一关。

`setRate()` 一律把值归到 **0.1 步进**：旧版存过 0.75 / 1.25 / 1.75 的用户读回来会落到
0.8 / 1.2 / 1.8，否则会出现「按钮显示 0.8x、实际跑 0.75x」。

倍速钮图标用**线性版** `ri-speed-line`（2026-10-17 用户第二次定版，先前试过填充版）；
`setRate()` 与首屏 HTML 里的初始图标必须同款。任务条（`.task-bar`，390 宽要塞 8 颗键）
只留数字、隐藏图标 —— 否则 `1.0x` + 图标会把「推进键独占一行」挤破。

## 影响面

- 云端失败自动降级本地、`voiceAcc` 口音点将、预取、IndexedDB 缓存：逻辑不变。
- 旧 key（含 `0.75`）不再被读取，历史坏缓存自然废弃。
- 计划时长：`rate` 仍是目标档，`secNew/secReview` 只除一次，无需改。

## 门禁

新增 `playwright-tests/journeys/app3/rate-cloud.spec.ts`（6 用例）：
1. 映射表：0.5/0.75 → 1，1.75/2 → 1.5，中间三档原样；
2. 0.75：请求体 `rate=1`、`playbackRate=0.75`、切 1x 不再发请求且命中同一条缓存；
3. 2x：请求体 `rate=1.5`、`playbackRate=1.333`，任何档位都不外发未支持值；
4. 菜单 8 项（7 预设 + 自定义）、单列、有滚动上限、激活项唯一；
5. 自定义面板口径 0.1/5/0.1，松手才落地，自定义值不硬凑预设高亮；
6. 0.1x 播放倍率不被下限抬成 0.25（`playbackRate` clamp 已放到 0.1）。

**反向验证**（均已实测必红后恢复）：
- `cloudSynthRate` 改回恒等 → 用例 1/2/3 红；
- `playRate` 固定 1（去掉补差）→ 用例 2/3 红。

## 已知边界

- 服务端若其实支持 0.75（另一种失败原因），本修法仍然正确：0.75 用 1x 音频放慢，音质略逊于原生慢速，
  但换取「所有档位都不依赖服务端枚举」。将来确认服务端支持后，只需把 0.75 加进 `CLOUD_SYNTH_RATES`。
- 播放层变速的时间拉伸质量由浏览器决定（Chromium/Safari 均为 time-stretch + 保音高），
  0.5x 极限慢速可能略有金属感；若用户反馈，可把 0.5 单独留在合成层（前提是服务端支持）。
