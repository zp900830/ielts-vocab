## 一、全站进度条盘点（实测，不是数类名）

| 位置 | 节点 | 现在能做什么 | 问题 |
| --- | --- | --- | --- |
| 播放条（常规模式） | `#seekTrack / #seekRail / #seekFill / #seekKnob / #seekTicks / #seekTip` | 能拖、能点刻度、悬浮出句子预览 | 桌面静止态轨道只有 **1px**、圆点把手 `opacity:0` —— 看不见就没人敢拖；键盘不可达 |
| **任务模式底栏** | `.tb-prog > #tbProg` | **什么都做不了** | 3px 装饰线，`aria-hidden="true"`，没有任何事件绑定。视觉上正好落在标题右边，读起来像一条分隔线 —— 他说"无法使用"就是它 |
| 今日面板 | `.tp-prog > .tp-prog-fill` | 只读 | 轨道色 `var(--border)`（暖米灰）在白卡上几乎看不见，读不出"还剩多少" |
| 顶栏 / 周历 | `.tp-week-bar` | 只读柱状 | 是图表不是进度条，本轮不动 |

**根因**：底栏那条线是 2026-09-22 那轮"底栏收成三个数"时**新加的视觉件**，只挂了 `setProg(width)`，从没接交互；而真正能拖的那根 `#seekTrack` 在任务模式里被 `.tb-play .ab-seek{display:none}` 整条藏掉了（当时写的是"同一能力由快速跳转那颗承担"）。于是任务模式下**一根都不能用**。

## 二、设计决定

**1. 底栏进度条 = 这一批的"位置尺"，拖到哪句就读哪句。**
- 复用播放条那套词汇（轨道 / 填充 / 把手 / 玻璃预览气泡），不新造第三种进度条；预览气泡直接共用 `#seekTip` 的样式（新增 `.prog-tip` 类，避免把那条玻璃配方再抄一遍 —— 上轮抽取实测站里已有 **8 份** backdrop-filter 写法）。
- **语义从"完成度"改成"位置"**：完成度条拖了不动手是死件，位置条拖了才成立。已读句数仍由主行那个 `0/36` 说，两者关系和播放器里"当前时间 / 已观看"一样。
- 命中区放大到 **28px 高**（视觉仍 4px 细线，靠伪元素外扩，不改条的高度、不动他定过的"一行三数"版式）。
- 键盘可达：`role="slider"` + `tabindex` + ← → / Home / End；焦点态必须看得见把手。
- 只在 ① 通读态可用；② 做题态、完成态、退出确认态自动禁用（`aria-disabled` + 不吃点击），因为那时"这一批"的坐标轴不是句子。

**2. 播放条那根：把"能拖"这件事做出来给人看。** 静止轨道 1px → 2px、把手由"悬浮才出现"改成**常驻 10px**（悬浮/拖动放大到 14px），手机沿用已有的常驻大把手；同样补 `role="slider"` 与键盘。

**3. 今日面板：只调可见性。** 轨道换成两档主题都读得出的中性色，填充加 1px 内高光与玻璃条同款圆角；数字不重复（`tp-num` 已经写了 `done / n 句`，不再往条上贴第二个数）。

## 三、验收标准（全部可机械判定）

落地在 `playwright-tests/journeys/shadow/progress-bars.spec.ts`（7 条）+ 两支探针 `work/round_g_probe.mjs`、`work/round_g2_probe.mjs`。**实测结果写在每条后面**，没有实测过的不写"已达标"。

1. 任务模式底栏：`#tbSeek` 存在且**不是** `aria-hidden`；`role="slider"`；`aria-valuenow` 随拖动变化；从 20% 拖到 80% 后当前句序号变化、填充宽度变化。
   → 实测：`aria-valuenow` 1→29（队列 36 句），`aria-valuetext`「第 29 句，共 36 句」，`.sent.playing` 下标 0→29。**反向验证**：同一支探针跑 `--base`（HEAD 复原的副本）报「任务条进度面 569.4×3px，热区 3px，role=无」「拖了不动」，闸门对旧代码响了。
2. 命中区：`#tbSeek` 可点矩形高度 ≥ 28px（390 与 1280 两档）。
   → 实测两档均 **28px**（`elementFromPoint` 从中心上下各探，上 14 + 下 13 + 本体 1，不是读 CSS 猜的）。锁里阈值定 ≥26，留亚像素余量。
3. 键盘：聚焦 `#tbSeek` 按 → 与 Home 各换一句。 → 实测 → 后 `aria-valuenow`=2，End 后 =36。
4. 状态门：`data-state=quiz|done|exit` 时拖它无效，且 `aria-disabled=true`。
   → 实现换了个更诚实的形式：只读态整根 `role` 改 `progressbar` + `tabindex="-1"` + `.off`，**把手 `opacity:0`**（露一个拖不动的圆点比没有圆点更让人以为按错了）。锁按这个形式判。
5. 版式不回退：底栏仍是"主行 + 辅行 + 一行按钮"，条高变化 ≤ 2px。
   → 实测 `.tb-line1` 高 = `.tb-title` 高 = **18.2px**（进度面没吃行高）；五次拖动后底栏高差 **0.0px**（390 档 102.6 / 1280 档 54.6）。
   **一个坑记在这**：刚进任务模式那一瞬 1280 档量到 57px，是按钮组 `transition:.4s` 没走完 —— 基线必须等高度稳定再取，否则这条锁自己造出"拖动把底栏改矮了"的假红。锁里用 `stableBarH()` 轮询到连续两次相同才返回。
6. 不越界、不遮挡：预览气泡在 390px 上不伸出视口左右边。
   → 实测 2% / 20% / 50% / 80% / 98% 五处 × 两档，左溢 / 右溢 / 上溢全为 **0**（气泡宽度按底栏宽裁，`min(气泡宽, 底栏宽 − 28)` 并以整条栏为锚夹住）。
   → 同一轮顺带量到：390 与 1280 档页面 `scrollWidth == clientWidth`（横向无溢出），`#tbKnob` 矩形落在 `#taskBar` 内（外扩热区写法最常见的"把手被裁"没有发生）。

## 四、本轮发现但【没修】的一条 → 下一轮（2026-09-24）已修，本节两条结论有一条是错的

跑门禁时 `cta-and-popups` 那条弹层锁**偶发红**，抓下来是一个跟进度条无关的真问题：

- 现场：390px 任务模式，倍速弹层最下面那一档（1.5x）点不到，Playwright 点名是 `#syncHint`「连不上云端 · 进度先记在本机」**intercepts pointer events**。
- 量到的几何：药丸矩形下沿 **671px**，末项矩形上沿 **671px** —— 贴到同一个像素。底栏高度是 `offsetHeight` 取整写进 `--task-bar-h` 的，差 1px 就压上去，所以红不红看运气。
- ❌ 当时写的根因「`.sync-hint` 的 `bottom` 里那 62px 是凭空抬的，正好把药丸送进弹层那条带子」——**2026-09-24 复测不成立**：真路径 `setSyncHint()` 会立刻调 `placeSyncHint()` 用 `getBoundingClientRect` 现量底栏顶边重写 `bottom`（390 任务模式实测内联 123px 对 CSS 132px），CSS 那条 calc 只是 JS 之前的兜底，用户看到的落点跟它无关。而按真路径量：390 两档弹层末项上沿 656 / 药丸下沿 706、1280 任务模式 循环末项 796.7 / 药丸下沿 825 —— **药丸和弹层用的本来就是同一条带（底栏顶边上方 8px 起），不管怎么落点都撞**。
- ❌ 当时写的「我试过、证明无效的一种修法：改 z-index 没用，因为药丸挂在 `.nav-menu` 里、父级自带层叠上下文」——**也是错的**。探针打出来的父级链 `#syncHint < .nav-menu < HTML` 里那个 `nav-menu` 是 **`<body>` 的状态 class**（同一支探针在别的时刻打出 `.task-mode`、`.ab-picking`），不是某个中间容器。药丸上面没有层叠上下文挡着，z-index 直接生效：实测把它从 595 降到 110，四颗弹层末项的 `elementFromPoint` 全部交还给按钮本身，两档四颗无一被压。
- ✅ 实际修法（2026-09-24，`agent/qoder-synchint-overlap-0923`）：`.sync-hint` `z-index: 595 → 110`，落到 `.audiobar`(120) / `.task-bar`(200) **之下**。口径是「被动状态 pill 给控件让位」，而不是去挪弹层或藏药丸 —— 弹层是他主动点出来的界面，药丸只是挂着的一条状态。
- ✅ 新增的锁在 `cta-and-popups` Case 5（三条：390 常规 / 390 任务 / 1280 任务）。它用「上传被拒」这条真路径让药丸显形，并先断言药丸确实在屏上；未修版三档全红、Playwright 点名 `#syncHint`，改完三档全绿。上一轮那条被撤的断言之所以量不到东西，是因为它用 `el.hidden=false` 强行显形 —— 量的根本不是用户看到的落点。
- 保留不动的一处：CSS 里那个偏高的兜底 `+ 62px`。它只在 JS 接手前的一瞬有效，且**偏高的方向是安全的**（宁可不压住栏上的按钮），改成"精确值"反而要靠 `--task-bar-h` 猜真实间距。注释已重写，把上面这两条错账标在原地。
